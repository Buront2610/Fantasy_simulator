# 冒険結果の構造化（統合設計書 §15.6）

## この段階の計画と実装範囲

1. 各分岐から `AdventureStepResult` と明示的な事実を返す。
2. シミュレーターは事実の種別・場所・参加者・原因・表示材料を正規イベントへ渡す。
3. 保存・再描画・個人史への接続と長期プレイを検証する。
4. 状態変更・記録・完了処理を原子的に適用する。

`AdventureRun.step()` / `resolve_choice()` の文字列リスト返却は互換入口として維持する。
内部の進行と選択処理には `step_result()` / `resolve_choice_result()` を使用する。
成果の型には今回実装した内容だけを含め、未実装の汎用変更エンジンは置かない。
既存のdataclassと正規イベントで実現できるため、新しいライブラリは追加していない。

## プレイ上の修正

- 偵察・発見・自動撤退を区別する。偵察を発見と誤認して繁栄度などを加算しない。
- 古い負傷の記録から、今回新たに負傷したと推測しない。
- 手動・自動の進行選択を記録する。撤退以外の選択も因果鎖から欠落しない。
- 負傷・死亡した同行者を主対象にし、他の隊員を副参加者として個人史から検索できるようにする。
- 参加者の隊内役割、選択内容、発見物、負傷前後の状態、冒険IDとステップを保存する。
- 既存の `summary_key` / `render_params` で再描画する。用語と選択名は表示時の言語に合わせる。
- ステップ間に死亡した隊長は選択できず、冒険の死亡記録と完了処理は一度だけ行う。

保存の外枠・schemaは変えていない。戦闘計算・危険確率・選択のゲーム上の効果も変更していない。
イベントの誤分類を直すため、発見に連動する噂・地域状態・共有体験の頻度は変わり得る。
その影響は既存の長期world-healthバンドで検査する。

## 原子的な適用

進行・選択は冒険、隊員、配偶者をコピーした限定的な世界上で計算する。
この計算には実世界へ書き込む代替経路を設けず、参照と結果を検証してから反映する。
一つの出発・進行・選択について、人物状態、冒険、正規イベントと通知、完了一覧、
地域の探索状態、追悼・別名・テンプレート履歴を一緒に確定する。

反映が例外で終了した場合は、対象オブジェクトの同一性を保ちながら元の値に戻し、
通常乱数・ID乱数の両方も復元する。出発の抽選、同行者・目的地の決定も復元対象とする。
履歴の上限整理によって削られた記録と各地点の参照も復元する。
イベントの読み取り索引は成功時には複製せず、失敗した場合だけ再構築する。
世界全体・地形・無関係な人物はコピーしない。

この境界の単位は冒険の一操作であり、複数の冒険や世界の一日全体を一括で巻き戻すものではない。

## 残る実装

- 汎用的な変更レコード、外部コマンドのリビジョン・重複送信契約は未実装。
- 目的・日程・補給の新モデル、選択ごとの実効性、救助の一周、実資産への報酬は未実装。
- 出発時点の記録と既存の文字列履歴は互換経路を維持する。今回の完了を§15全体の完了とは扱わない。
