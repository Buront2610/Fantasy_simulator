# 01. 文書の位置づけと要求の確定範囲

## 1.1 本書が統合するもの

本書は、コード品質の改善計画だけではなく、世界観上の目的、ゲーム上の判断、シミュレーションの因果、保存形式、開発順序を一体として定義する。前のレビューで挙がった不整合は拡張の前提として扱うが、機能の価値を不具合一覧だけで評価しない。

参照コミットは、会話中で確認された固定スナップショットである。文書作成時点の最新ブランチとの一致や、リポジトリ全体のテスト成功を新たに保証するものではない。既存コードに関する記述は付録Dの参照範囲に基づき、局所検証・コード読解に由来する問題は、本体の回帰テストで再確認してから修正する。

## 1.2 ユーザー意図として確定している要求

| 要求ID | 採用する方向性 | 設計への反映 |
|---|---|---|
| R-01 | 言語エンジンは言語史の表現を目指す | 祖語、分岐、継承、接触、古語、史料を第一級の対象にする |
| R-02 | 婚姻には文化的差異がある | 近親関係・若年での婚姻を含め、成立・承認・評価を文化規則にする |
| R-03 | 世界が継続的に変化する | 生活・社会構造・神話的変化を異なる頻度と時間尺度で扱う |
| R-04 | 文明の勃興、経済、宗教を扱う | 集約人口、集落、制度、物流、宗教共同体を導入する |
| R-05 | 魔法、ダンジョン、遺跡を扱う | 超自然法則、資源・設備、起源・現在の脅威を分離する |
| R-06 | 魔王出現・勇者誕生などの大規模シナリオを扱う | 長期過程、複数の役割、分岐終結、社会的余波を持たせる |

言語のモチーフは、特定作品の語彙を複製することではなく、共通祖先から異なる歴史を歩んだ言語の対応が見える構造である。「祖語→言語A→言語B」という直線を固定せず、分岐と再接触を表現する。固有語彙・音韻・物語は本作固有の設定として作る。

## 1.3 提案として採用する設計判断

本書は、重要人物と集約人口の併用、意味構造を先に持つ言語・史料、複数の承認主体を持つ婚姻記録、在庫と輸送による経済、シナリオ定義と実行事例の分離を推奨する。これらはユーザーが個別の型名まで指定したものではなく、要求を実現するための設計案である。

初期コンテンツの文化数、神の実在形式、魔法の代償、婚姻慣習の具体値、シナリオの発生頻度は未確定である。実装を進めるための仮値は付録Cに隔離し、歴史上の一般法則やゲームの確定バランスとして扱わない。

## 1.4 現行実装との関係

現行には、日単位進行、構造化イベント、関係・性格、冒険、戦闘、噂、世界の記憶、地形・地点・経路、設定バンドル、言語生成、長期アーク、保存移行の基盤がある。[S01–S12] 一方、経済の在庫・輸送モデル、宗教組織の本格的実行モデル、文化別婚姻制度、歴史段階を固定した言語系統、大規模シナリオの完成形は、追加設計として扱う。

現在の公式な実装順序の正本はリポジトリの `docs/implementation_plan.md` である。本書を採用するときは、同文書へ採用範囲・計画アンカー・受け入れ条件を反映し、並立する二つの命令書にしない。既存の「基盤導入済み」と「ゲームとしての循環完成」を別の達成段階として記載する。[S02]

# 02. プロダクト像とゲームの中心循環

## 2.1 中心体験

異なる文化を持つ人々が暮らす世界を観察し、その言葉・制度・家・土地の由来をたどり、重要な局面で限定的に介入する。個々の判断が関係・技術・交易・文明へ積み重なり、世界が大事件を経験した後も、その余波の中で生活と歴史が続く群像・文明史シミュレーターとする。

言語史を読むこと、家系と学派の分岐を眺めること、土地に残る複数時代の痕跡を比較すること自体を体験価値とする。すべてを戦闘報酬や謎解きの鍵に還元せず、世界の由来を理解する観察を成立させる。

## 2.2 基本のゲーム循環

```text
世界・人物・史料を観察する
  → 注目対象と関心事を選ぶ
  → 人物や組織が状況を判断する
  → 必要な場面で介入または委任する
  → 行動と世界法則から結果が生じる
  → 結果が関係・資源・土地・制度を変える
  → 記録・噂・言語・伝承に痕跡が残る
  → 変わった世界を再び観察する
```

観察だけの操作は、世界の状態やシミュレーション用乱数を変更しない。調査・聞き取り・解読研究のように時間や資源を使う行為は、閲覧ではなく明示的なゲームコマンドとして扱う。

## 2.3 プレイヤーの立場

標準は観察者モードとし、世界全体の構造と年代記を閲覧できる。人物へのズームでは、その人物が知っている情報と実行できる行動に絞る。二つのモードは混同せず、画面上で視点と情報範囲を明示する。

お気に入りや注目設定は、原則として通知・編集・表示へ作用する。注目しただけで生存率や事件確率を変更しない。救助の手配、方針の変更、組織への支援など、因果を変える操作は効果・費用・実行主体を明示する。神の視点での世界編集は、通常プレイと分けた開発・サンドボックスモードにする。

## 2.4 変化の三層

| 層 | 主な変化 | 時間と表示の方針 |
|---|---|---|
| 生活 | 出会い、婚姻、成長、修行、移住、養育、継承 | 頻繁に起こるが、表示は注目対象を中心に編集する |
| 社会構造 | 都市成長、交易再編、宗派・学派・言語の分岐 | 条件の蓄積と持続期間によって変わる |
| 神話的事件 | 魔王、勇者、広域魔法災害、文明規模の危機 | 稀な長期過程とし、前兆と復興期間を持つ |

静かな時期を失敗と見なさず、教育や家の成長などを見せる。画面が寂しいことを理由に世界へ災害を注入しない。出来事の選択と、その表示上の重要度の選択は別の処理にする。

## 2.5 初期段階で主線にしない機能

巨大マップ、全住民の毎日の会話、自由自然言語だけで駆動するNPC、大量の商品と職業、全員操作の戦術戦闘、オンライン常時世界は初期必須としない。将来拡張を妨げない境界は設けるが、先に少数の人物・地点・制度で循環を完成させる。網羅的な現実社会の再現ではなく、本作で観察・判断できる因果を優先する。

# 03. 設計原則とアーキテクチャ

## 3.1 十の設計原則

| ID | 原則 | 実装上の意味 |
|---|---|---|
| P-01 | 事実と解釈を分ける | 実際の出来事、噂、信仰上の主張、推測を別データにする |
| P-02 | 現在状態の正本を一つにする | 負傷・在庫などを複数の可変フィールドで競合させない |
| P-03 | 起源と変更履歴を残す | 同じ語・人物・物品・地点をIDで継続追跡する |
| P-04 | 継承と接触を分ける | 系譜からの派生と、借用・交換を異なる関係にする |
| P-05 | 文明を優劣の一本の数値にしない | 技術・交通・組織・人口・記録などの複数軸を使う |
| P-06 | 文化規則と個人の意思を分ける | 制度上の可能性を、当人の希望や全員の行動と同一視しない |
| P-07 | 選択には実際の差を持たせる | 文言だけでなく費用・時間・結果分布を変える |
| P-08 | 観察は非破壊にする | 表示や翻訳で世界の乱数・結果を変えない |
| P-09 | 失敗後も世界を続けられる | 勇者の死、王国の崩壊、救助失敗を通常の歴史として扱う |
| P-10 | 保存可能・検証可能な単位で作る | 正規データ、移行、回帰条件を機能と同時に定義する |

## 3.2 レイヤー構成

```text
UI / CLI / 将来の別フロントエンド
                ↓
Application Services / Commands / Query Views
                ↓
Simulation Scheduler / Intent Resolution / Arc Drivers
                ↓
Domain Services / Rule Evaluation / State Transitions
                ↓
World Aggregates / Canonical Records / Typed State
                ↕
Persistence / Migrations / Derived Indexes
```

UIは表示と入力遷移を担当し、ドメインは端末やファイル保存を知らない。Application Serviceはコマンドの妥当性・実行範囲・結果をまとめ、個々の能力式や文化規則を持たない。Worldは集約の窓口に留め、すべての処理を巨大なMixinへ追加し続けない。既存の分割を生かして領域サービスと明示的な依存へ移す。[S03,S04]

## 3.3 更新パイプライン

更新は「現在状態を読む→意図・候補変更を作る→前提条件を検査する→変更を適用する→事実イベントを記録する→必要な派生索引を更新する」の順とする。検証済みの変更と記録は、同一の論理単位として一度だけ確定する。

全世界を毎回コピーする必要はない。影響範囲を限定した変更セットと事前検証を使い、途中で失敗した場合に人物だけ変化して履歴がない状態を残さない。既存 `world_change/` の方式を参照しつつ、他領域へ必要な範囲で展開する。UI上の文章から変更内容を逆算しない。

## 3.4 正本の三分類

人物の健康、在庫、組織の資源などの現在実体は、領域集約の保存状態を正本とする。時代別の言語変化や歴史的命名のように再構築が重要な領域は、基点と確定した変更履歴を正本とする。表示用の集計、地図のラベル、到達可能性の索引、通知候補は派生データとする。

`World.event_records` は構造化された出来事の正規ストアだが、現行の全状態を完全に再生できる万能イベントソースと見なさない。どの領域がスナップショットを正本とし、どの領域が履歴再生を契約とするかを一覧管理する。[S03,S11]

## 3.5 ID・役割・因果の共通契約

人物・共同体・言語段階・語・地点・家・婚姻・物品・シナリオには安定IDを付ける。表示名の改定は参照先の変更ではない。イベントの参加者は単なる配列だけでなく、実行者、対象、同行者、目撃者、被害者などの役割を持つ。

`cause_event_ids` は結果の計算や判断に実際に使った原因を参照する。時間的な前後関係や同じ話題は `related_event_ids` に置く。真の因果グラフは過去方向への参照とし、循環した原因を作らない。俗説上の因果は主張データに保持し、事実イベントの因果を置き換えない。

# 04. 時間・処理順序・乱数・解像度

## 4.1 共通時刻

内部の物理的時間は、世界の起点から単調増加する `world_tick` を正本とする。初期の粒度は日とし、日内の複数更新には `sequence_no` を付ける。前史を含む起点、暦換算表、保存されたルール版を合わせて、同日の順序を一意にする。

既存の `elapsed_days` はシミュレーション開始からの経過値として互換性を保ち、前史を含む時間軸との対応を明示する。歴史イベントの `absolute_day` を曖昧なまま転用しない。移行時には旧開始時点と新起点のオフセットを保存する。

文化ごとの暦、年号、祭礼周期は時間の表現または社会的周期であり、暦変更で移動残日数や生物的な成長が加速しない。成長は基準となる太陽年相当期間や種族設定の期間で評価し、表示上の一年と無条件に同一視しない。[S13]

## 4.2 更新周期

| 対象 | 基本周期案 | 注意点 |
|---|---|---|
| 健康、移動、冒険、期限 | 日単位または予定時刻 | 期限と到着を同じ時間軸で比較する |
| 生産・消費・輸送割当 | 日集計または固定長の経済期間 | 文化暦の月長で年間生産が勝手に増えない |
| 家・教育・組織の意思決定 | 活動予定、週相当・月相当 | 無意味な全員毎日再計算を避ける |
| 集約人口 | 固定期間・生活史イベント | 個別人物との二重計上を防ぐ |
| 言語接触と文化変化 | 接触集計＋長期間の評価 | 事件直後の全言語即時変化を標準にしない |
| 大規模シナリオ | 前提変更または予定評価 | 毎日無条件に段階を進めない |

周期は実装時に確定する設定値とする。変化する経路・参加者・前提条件に対しては、予定を無条件に維持せず再評価する。周期変更はルール版変更として扱う。

## 4.3 日次処理順序の初期契約

日開始時の確定状態から、環境と期限を評価し、人物・組織の意図を作る。競合する資源や対象を調停した後、移動・作業・冒険の到達や成果を適用する。救助・治療・負傷の結果を統合して健康状態を確定し、死亡の後処理を一度だけ行う。期間境界なら人口・経済・長期アークを更新し、最後に通知と読み取りモデルを構築する。

同日に救助到着と健康悪化の期限が重なる場合は、保存された `due_tick` と優先順位で解決する。初期案は「その日の期限までに到着した有効な救助を評価した後に健康期限を解決」とする。これは公平性のための提案仕様であり、実装前に決定記録へ固定する。呼び出し順の偶然に任せない。

## 4.4 複数解像度

重要人物は個別に、背景住民は集団として管理する。前史は主要転換点による粗い更新、プレイ開始後は日単位の更新とする。粗い前史と精密なプレイの結果が完全一致すると主張せず、人口・資源・継承・参照の不変条件と保存契約を共有する。

集約住民から個人を具体化する処理では、その人物を集団から差し引くか、集団のうち個別管理されている人数として印付けする。初期案は「総人口は集団側に含め、個別人物分の変動を同じ台帳へ反映する」方式とし、二つの人数を加算しない。

## 4.5 乱数と決定性

シミュレーション、ID生成、前史生成、言語、文章表現の乱数を分離する。新機能は、世界シード・領域・実体ID・ローカル更新番号・ルール版から導く乱数系列を推奨する。無関係な言語の追加や閲覧操作で、既存人物の未来を変えない。

候補集合は安定した順序にし、同点処理を明文化する。Pythonの集合列挙順、プロセスのハッシュ、壁時計、ランダムUUIDの暗黙使用に依存しない。浮動小数点の集計順も固定し、在庫等は整数・固定小数を優先する。同じシードであってもルール版が違えば同じ未来を保証しない。

# 05. 世界の主要データと参照契約

## 5.1 独立して存在する概念

種族、文化、言語、宗教、国家、文明圏、家、世帯は別実体とする。複数の文化が同じ言語を共有し、一文化が複数の宗教を持ち、政治組織が滅びても文字や祭礼が残ることを許容する。所属は有効期間を持つ参照で管理し、人物・場所の単一文字列へすべてを押し込めない。

## 5.2 集約と所有者

| 集約 | 正本にする主要状態 | 主な参照 |
|---|---|---|
| Character | 生死、現在健康、能力、技能、現在地、意思 | 家、世帯、文化・言語知識、所属組織 |
| Household / House | 同居と養育／家名・継承・財産の連続性 | 個人、婚姻、資産、出来事 |
| Union | 婚姻・結合の成立事実と取り決め | 当事者、制度版、承認主体 |
| Settlement | 背景人口、設備、在庫、生産、需要 | 地点、文化、経路、組織 |
| Organization | 構成員、資源、意思決定、継承規則 | 拠点、支配・権利、信仰・学派 |
| Language Stage | 特定時点の言語状態または再構築基点 | 祖先段階、語、変化、共同体 |
| Site / Ruin / Dungeon | 位置・歴史層／過去の用途／現在の脅威 | 遺物、設備、経路、冒険 |
| Arc / Scenario | 長期過程の段階、役割、予定、確定した進行 | 対象実体、原因・関連イベント |

同一の在庫を集落と組織の両方が正本として保持しない。所有者と保管場所を別にして、資産台帳で一度だけ数える。現在の行政支配と、財産権・信仰上の権利も異なる関係として記録する。

## 5.3 共通の履歴レコード

履歴には `record_id`、`occurred_tick`、`sequence_no`、種別、役割付き参加者、対象ID、変更内容、因果参照、作成時のルール版を持たせる。表示用の `summary_key` と `render_params` は事実から作り、ローカライズされた文章を新しいゲーム判断の入力に戻さない。

歴史上の名称や刻文のように「当時の文字列」自体が資料になるものは、表示用文章のキャッシュと区別し、作成時の表面形を固定保存する。現在名で見せるための注記は別の読み取りモデルが担う。

## 5.4 定義・実行状態・投影

`SettingBundle` は作者が記述する静的な初期定義を持つ。文化・婚姻規則、宗教、魔法法則、資源、言語、シナリオ定義のスキーマを段階的に追加する。実行中の制度変更や分岐は定義を書き換えるのではなく、版付きの状態・履歴として追加する。

UIのダッシュボード、家系図、言語系統図、文明年表、輸送状況は投影である。状態更新の際に必要な投影だけ無効化し、読み取りで新規実体を生成しない。キャッシュの鍵に必要な状態リビジョンを含める。

# 06. 文化・婚姻・親族・世帯の制度

## 6.1 文化差を前提にする

近親関係や若年での婚姻を含め、どの関係が制度として成立できるかは文化規則によって異なる。現代の特定社会の年齢や禁止範囲を、すべての文化の固定条件にしない。婚姻・婚約・同居・養育・相続・恋愛感情を別の軸で表現する。

若年の関係がその文化で婚姻として成立する設定を、必ず婚約へ読み替えない。一方、婚姻の成立だけで身体能力、教育段階、遠征への適格性、出生処理を一括で変更しない。婚姻に関する表現は制度・関係・生活史として記録し、性的な場面の生成を本設計の対象にしない。

## 6.2 文化規則の構造

`CultureDefinition` は、命名、親族、婚姻、居住、継承、儀礼などの規則群への参照を持つ。`MarriageNorms` は版付きとし、全世界共通の一つの可否フラグにしない。初期版では婚姻を中心に実装し、他の文化項目は明示的な未対応状態を返す。

| 項目 | 内容 | 実装上の注意 |
|---|---|---|
| 成立段階 | 婚約・婚姻・儀礼と、生活段階の条件 | 若年での制度成立と生物的成長を混同しない |
| 親族規則 | 親子・きょうだい・いとこ・同氏族・養子等 | 血縁と社会的親族を別判定にする |
| 選好 | 家、地域、文化、地位、既存関係 | 成立可能性とは別の重みにする |
| 手続き | 当人の判断、家の交渉、宗教・行政の承認 | 誰が何を決定したかを保存する |
| 居住と所属 | 新世帯、いずれかの家への加入、別居 | 婚姻と住所を直接連動させない |
| 財産と継承 | 合意された財産移転、家名、相続 | 実際の資産台帳へ一度だけ適用する |
| 解消と再成立 | 死別、解消、再婚、取り決めの変更 | 過去の成立記録を削除しない |

## 6.3 親族判定

親子の系譜は明示された親参照、養親参照、家・氏族への所属から計算する。`family` タグは夫婦や共同養育にも付くため、タグ一つを親族規則の代用品にしない。[S06]

`KinshipView` は関係種別、血縁系譜の経路、養親・社会的関係、情報の確実性を返す。情報不足の場合は「無関係」と断定せず `unknown` とし、文化や承認主体の規則が不明系譜をどう扱うかを明示する。系譜上の親子循環は拒否し、複雑な親族関係でも探索が無限にならない。

近親関係の制度上の評価と、健康・遺伝のモデルは分離する。初期版は遺伝的影響を推測して自動付与せず、必要になった場合は独立した生物モデルと検証を追加する。文化の許容・不許容を人物能力の優劣へ変換しない。

## 6.4 適格性・選好・承認・個人意思

判定は四段階とする。第一に規則上の成立可能性を調べ、第二に当人や家の候補評価を行い、第三に交渉・決定を解決し、第四に主体ごとの承認状態を記録する。好感度は候補評価の一部であり、婚姻そのものではない。

文化が慣習を認めていても当人が望むとは限らない。希望、圧力、義務感、家の都合、相手への感情を区別し、合意、拒否、延期、条件変更、移住などの行動につなげる。制度上の成立と、関係の親密さや葛藤を別に記録する。

## 6.5 UnionRecordと承認主体

`UnionRecord` は当事者、成立時刻、制度IDと版、取り決め、終了時刻・理由、家・世帯への効果を持つ。宗教組織、氏族、国家、共同体による認定は `RecognitionRecord` の集合で表す。ある主体には認められるが別主体には認められない関係を保持できる。

初期版は二者間の婚姻を実装範囲としてよいが、内部参照を常に単一の `spouse_id` だけに固定しない。複数の結合を扱う設定を導入する場合は、同時成立条件と財産・養育の規則を伴わせる。既存 `spouse_id` は明確な互換条件でのみ投影し、複数候補から無言で一人を選ばない。

## 6.6 家・世帯・文化変更

`Household` は居住と養育、`House` は家名・財産・系譜・社会的連続性を担う。婚姻後も元の家との関係、複数の言語、異なる慣習が残り得る。子どもの家名、教育先、使用言語は婚姻時の取り決めと実際の養育環境から決まり、種族だけで固定しない。

制度変更は有効開始時刻と適用範囲を持つ。新しい規則で過去の婚姻成立を消さず、既存関係の認定変更が必要なら新しい出来事として記録する。人口全体の慣習変化と一件の例外的承認も別扱いにする。

## 6.7 受け入れ条件

同じ二人・同じ関係値でも文化設定によって成立可能性や承認が変わること、若年での婚姻成立が冒険参加能力を成人相当にしないこと、制度改定後も旧婚姻の根拠が残ること、親族不明を無関係へ勝手に変えないことを検証する。家系、財産移転、関係の終了は途中保存を挟んでも一度だけ適用される必要がある。

# 07. 人物の生活史・家・誓約・意思決定

## 7.1 生活段階と出生

人物生成は種族・出身・養育環境・生活段階を決めてから、能力・技能・名前を作る。通常の成人向け人物を生成した後、年齢だけを0へ変更する経路を置き換える。[S06] 生得的素質、現在使える能力、教育によって得た技能を可能な範囲で分け、誕生時から完成した職業人にしない。

生物的成長段階、文化的成人資格、特定活動への適格性を別規則にする。子ども向けの生活・教育・家族との移動は許容し、通常遠征や戦闘への参加を婚姻状態から推測しない。活動条件は候補抽選時と直接実行APIの両方で共通関数を使う。

出生は世界共通の通常イベント枠から切り離し、生活史と人口動態の条件で評価する。婚姻がなくても成立する養育や共同体の制度を必要に応じて定義できる形とし、出生・親子・養育の関係を明示する。初期版の細かな人口率は統計テストで調整する暫定値とする。

## 7.2 性格・経験・行動

既存の五軸性格、特徴、共有経験、関係の転機を利用する。[S05] 行動選択は「世界共通のイベント種類を抽選して人物を割り当てる」方式だけでなく、活動する人物を選び、実行可能な行動を集め、性格・関係・健康・場所・経験・目標で重みを付ける方式へ段階移行する。

重みは命令ではなく選好とする。同じ性格でも資源や状況で行動が変わる。冷却期間、終了条件、実行不能時の代替行動を持ち、好奇心の高い人物が永遠に同じ遺跡へ出発するようなループを防ぐ。判断に実際に使った要因を `DecisionTrace` として記録し、後から理由らしい文章を捏造しない。

## 7.3 家と初期背景

既存の出自・没落・離散・育ち・家の負債などは、まず表示用キーとして保持されている。[S07] 将来は、世界内に存在する家、故郷、師匠、負債、事件と結び付ける。初期人物の背景を具体化する際は、関連実体を同時に作り、相互矛盾を検査する。

既存の背景文だけから、過去の親や財産を一意に復元できない場合は、説明用の背景と未確定の実体情報を区別する。移行で架空の両親や借金額を突然確定しない。

## 7.4 誓約と葛藤

`Vow` は誓った人物、受益者または対象、約束の内容、成立イベント、履行条件、期限、継承可能性を持つ。初期状態は `active / fulfilled / broken / released` とし、必要な場面だけ `contested` を追加する。性格の `oathbound` と、具体的な誓約の存在は別データにする。

救助の約束と家族の避難、土地の防衛と遠征義務など、複数の目的が競合することを許容する。断念だけでなく、支援依頼、条件再交渉、受益者からの解放も解決経路にする。誓約の承継は社会的期待と本人の引受けを分け、子孫へ自動的に意思を付与しない。

## 7.5 継承と長寿

継承対象は家名、財産、技能、史料、権利、遺物、未解決事項とする。血縁、養子、弟子、組織による継承を区別し、各制度に従って処理する。人物の死がすべての知識と物語の削除にならないよう、伝授済みの知識や譲渡済みの品は受け手に残る。

長寿人物は生きた史料になり得るが、年齢が高いだけで全事件を知るわけではない。目撃、伝聞、読書、推測を区別した知識を持ち、誤った伝承や記憶の偏りも主張として扱う。本人の生涯と家系の世代数が異なる速度で進むことを年表で比較できるようにする。

## 7.6 受け入れ条件

教育前後で可能な行動が変化すること、成長や婚姻で職業が無条件に上書きされないこと、誓約が判断と関係の変化へ返ること、同じ家の履歴が複数世代へつながることを確認する。未知の背景の具体化が過去の正本を書き換えないことも必要とする。

# 08. 言語史生成エンジン

## 8.1 目的と評価基準

言語エンジンは、命名補助ではなく、祖語から現在へ至る言語史の生成・保存・比較・観察を担う。音の美しさと規則の一貫性を両立し、共通祖先を持つ語や文法が、別の歴史を経て異なる姿になることを表現する。探索や解読への利用は重要だが、それだけを完成条件にしない。

評価軸は、同源語の対応が見えること、独自の言語らしさがあること、変化の時代順を説明できること、既存の名前と史料が安定すること、言語の系譜と共同体の使用史を区別できることとする。すべての言語を均等な頻度で変化させる必要はない。

## 8.2 現行の足場と設計差分

現行には `LanguageDefinition`、親言語参照、語族、意味付き語根、語根の言語別実現、条件付き音変化、命名トレース、言語変化履歴、生成された現地名がある。[S08,S09] これらを全面廃棄せず、現在の文字列中心のプロファイルと設定継承を、歴史段階と語の同一性を持つ構造へ拡張する。

当面は、既存の `generate_toponym()` や `profile()` の公開入口を保ちながら、内部に構造化語彙と命名記録を追加する。旧データは旧生成規則で再現できる経路を維持し、生成アルゴリズムの変更を無断で過去へ適用しない。

## 8.3 データモデル

| 型 | 必須の内容 | 正本としての役割 |
|---|---|---|
| LanguageFamily | 語族ID、祖語段階、表示・作者設定 | 分類と生成方針。祖先関係そのものとは別 |
| LanguageLineage | 系統ID、祖先段階への参照 | 分岐後の言語の連続性 |
| LanguageStage | 段階ID、成立時刻、音韻・文法・語彙基点 | 特定時代の確定状態または再構築基点 |
| Lexeme | 語ID、意味・語義、品詞、語源、導入時点 | 語形が変わっても継続する語の同一性 |
| CognateSet | 祖先語または祖先語根と派生語の対応 | 同源関係。意味が同じだけでは作らない |
| LanguageChange | 変化ID、段階、規則、適用時刻、対象範囲 | 歴史的変化の確定記録 |
| LoanRecord | 借用元・先、語ID、借用時点、適応過程 | 継承ではない語の流入 |
| LanguageCommunity | 使用地点、話者集団、用途、接触 | 言語使用の社会的な現在状態 |
| Orthography | 音・文字の対応、用途、時代 | 発音とは別の表記体系 |
| NameFormation | 選んだ語・構成・命名時点・理由 | 名称を再抽選せず変化させる基点 |

型名は提案であり、既存の定義と重複する型を無計画に増やさない。静的な `LanguageCommunityDefinition` は初期条件、動的な共同体状態は使用状況として区別する。

## 8.4 意味・語・語形を分ける

`meaning_key` は世界で扱う概念、`lexeme_id` はその言語内の語、音素列や表記は語の時代別の形を表す。一つの語が複数の意味を持ち、一つの意味に複数の語が対応できる。別言語で意味が同じでも、同源語とは限らない。

初期語彙は、地形、移動、方位、建造物、親族、誓約、宗教、交易、危険、魔法技術など、世界で使う意味を優先する。意味付き語根の既存プレビューを通常の命名へ接続し、最終文字列に都合のよい語源を後付けしない。意味不明の既存語は不明なまま保持する。[S09]

派生語・複合語は、元の語IDと形成規則を保持する。同音化した語を表面形の重複除去だけで統合せず、意味と語源の異なる語を残す。語彙数の上限は表示用サンプル数と正規語彙数を分け、親語彙が多いだけで子言語独自の明示語が切り落とされないようにする。

## 8.5 音素と表記の分離

内部では安定した音素IDの列を扱い、`sh` などの文字列が一音か二音かを宣言する。規則の対象文字列を音素一覧へ自動追加したために既存語の分割が変わる構造を改める。複数音の規則は `source_segments` と `target_segments` の配列で表す。[S08]

発音の特徴は母音・子音、必要な調音特徴、強勢、長短などを明示する。綴りに特定文字が含まれることだけで母音や子音を推測しない。初期版は使用する規則に必要な特徴へ限定し、汎用的な音声学体系の完全実装は求めない。

Unicodeの入力正規化方針は固定し、検索用の正規化と正式表記を分ける。名前の短縮は音節または形態素境界で行い、複数文字の音を途中で切らない。UIの省略記号は表示専用であり、正式名を変更しない。

## 8.6 音韻的個性

音素の頻度、語頭・語末の許容音、子音連続、音節型、音節数、強勢を言語別に持たせる。語末母音が多い言語、短い閉音節が多い言語、複合語を好む言語などを、同じ単語の長さ調整だけで表現しない。

母音が接する場合の融合・脱落・挿入は言語別の規則とする。全言語で接合部の母音を一文字消すような整形は旧ルール版に閉じ込める。生成失敗時は有効な簡単な構成へ戻し、規則違反の文字列を切り詰めて成功扱いにしない。失敗理由とフォールバック回数を作者向けに報告する。

## 8.7 歴史的変化と共時的規則

歴史的な音変化は、その時点の語形へ順に一度適用する。現在の言語で語を組み立てる際に起こる音の調整は、共時的な規則として別管理する。反復が必要な規則は個別に宣言し、歴史上の規則全体を安定するまで何度も回さない。

```text
祖形：papa
古い変化：b > v
後の変化：p > b
歴史順の結果：baba

後の変化でできた b に、終了済みの古い変化を再適用しない。
```

各段階で、入力語形、適用規則、出力語形、適用した条件をトレースできるようにする。規則の対象外だった理由もデバッグ表示で確認できる。変化前後の形を比較して生産性を測るが、変化候補がない年を異常としない。

## 8.8 文法の歴史的派生

初期文法は、複数、所有、簡単な否定・命令、名詞と修飾語の順序、名前の複合から始める。祖語の形態を娘言語が継承し、音変化・再分析・類推によって別の形になることを表現する。単語だけを別文字列へ置換した共通文法に限定しない。

```text
説明用の架空例：
祖語：tala「谷」 / tali「谷々」
A系統：tala / tali を保持
B系統：複数語尾 i による a > e、その後に語末母音が脱落
B系統：tal / tel
```

同じ音変化が語彙と文法へ一貫して作用することを優先する。不規則な現代形には履歴上の根拠を持たせ、形を複雑にするためだけの例外を大量生成しない。新しく借用された語や新語には、導入後の変化と現在の文法規則だけを適用する。

## 8.9 分岐・借用・接触

娘言語は「現在の親プロファイル」ではなく、分岐時点の親段階を参照する。祖先側で後から起きた変化は、娘言語へ自動的に逆流しない。継承は原則として有向非循環の系譜、交易や借用は別の接触グラフで管理する。

借用は、借用元の語と時点、受け入れ側の音への適応、意味領域、語形変化を記録する。接触相手によらない固定語幹をすべての言語へ追加する方式から段階的に移行する。婚姻・移住・教育・交易・征服は接触量と使用領域を変える原因であり、戦争なら必ず特定の音変化という普遍則にはしない。

地域共同体では、日常語、通商語、行政語、典礼語、学術語が併存できる。言語変化の速度、社会的普及率、個々の人物の理解度は同じ数値にしない。方言が分かれても作者上の分類が即座に別言語になる必要はなく、分類と相互理解を独立に扱う。

## 8.10 命名と名前の歴史

命名は、土地の命名時点の特徴、命名者、事件または文化的慣習から意味を選び、語、構成、発音、表記を順に実現する。構成を一度固定し、新しい語彙や接尾辞が追加されても既存名の材料を再抽選しない。

`NameRecord` は現地名、外部名、公称、旧称、愛称、宗教名などの種類と、使用共同体、有効期間、元の命名記録を持つ。発音変化と正式な改名は別イベントとし、旧名は現在地点IDへ参照可能なまま残す。固有名の変更で索引が壊れないことを保証する。

人名は文化の家名・親名・出身地・職能・成人時の改名・功績名に対応できるようにする。すべての文化を同じ名＋姓形式に固定せず、実装する命名方式ごとに婚姻・継承との接続を定義する。既存人物の名前はルール更新だけでは変更しない。

## 8.11 史料・碑文・古語

史料は「世界で起きた事実」ではなく「特定の作者が、ある時点に残した主張」を持つ。内容の意味構造、使用言語段階、文字体系、当時の表面形、媒体、作者、現在状態を固定する。訳文は意味構造と観察者の理解から生成する。

古い言語は、話者が減っても儀礼、詩、契約、命名、魔法書に残り得る。長寿人物が覚えている形と公文書の標準形が異なることも許容する。すべての古語を「現代語の難しい版」として扱わず、学習経路と使用域を持たせる。

## 8.12 生成・保存・性能

言語系のシードは、世界言語シード、系統ID、対象の更新番号、生成規則版から導く。世界全体の履歴件数を利用し、無関係な言語のイベントが別言語の未来を変えることを避ける。意味と語の生成、史料の内容、表記のレンダリングの乱数も分離する。

履歴が正本の領域では、ランタイムキャッシュより確定履歴を優先する。再生可能な基点・規則版・順序を保存し、規則版を変えた場合の移行か旧規則再生を明示する。既存の歴史優先・ランタイムキャッシュという方針を、語と段階にも拡張する。[S08,S09]

全語を毎年再計算せず、変更された段階・語群の表面形を必要時に生成してキャッシュする。履歴の大量化はチェックポイントで扱うが、元の履歴を削った基点を単なる破棄可能キャッシュとは呼ばない。

## 8.13 作者用ツールと受け入れ条件

語源トレース、段階間比較、同源語一覧、借用一覧、名前生成の構成、影響する規則、欠けた意味語根、フォールバック、語形衝突を確認できるCLIを追加する。文法・音韻の制約を満たすことと、作者の望む美的傾向を両方検査する。

必須テストは、規則追加による不意の分割変更がないこと、歴史順が保持されること、娘言語へ分岐後の祖先変化が逆流しないこと、同音化で語源が失われないこと、古文書が現在語へ書き換わらないこと、語彙追加やUI言語変更で既存名が変わらないこととする。語源不明の旧データには、存在しない意味を割り当てない。

# 09. 知識・教育・学派・情報の理解

## 9.1 知識の種類

人物の知識は、事実を知る、誰かの主張を聞いた、ある技法を習得した、語や文字を読める、といった種類に分ける。実際の世界状態を知識欄へ常時同期せず、目撃・伝聞・教育・史料による更新イベントを通す。

既存 `known_languages` は初期熟達度の互換入力として生かす。将来は会話、文字、古語、専門語の知識を分けるが、すべてを初期から細分化せず、読解・古語への補正から導入する。読み取りだけで熟達度や乱数を更新しない。[S10]

## 9.2 理解と信頼性

読める文字、分かる語、理解できる構文、時代特有の用法を段階的に表示する。低理解度では未知や候補の幅を示し、無作為な誤訳を毎回返さない。誤読が必要な場合は語の類似や多義性など根拠を持たせ、同じ条件の再閲覧で結果を変えない。

史料を完全に読めても、その内容が事実とは限らない。言語理解、資料の真正性、主張の確かさ、伝聞の独立性は別判定とする。反証を得た場合も、誰が訂正情報を知ったかを記録する。

## 9.3 師弟と技法

既存の師弟タグと技能レベルを、伝授の対象となる技法へ接続する。[S05,S12] `Technique` は基礎技能、派生元、効果と代償、必要条件を持ち、`TransmissionRecord` は誰が誰から、またはどの史料から学んだかを記録する。

技法の改良は常に上位互換にせず、速度・消耗・安全性・射程・準備などの交換関係を持たせる。数値効果の定義と系譜の記録は分離し、系譜名だけで戦闘力が上がるようにしない。学派の分裂は技法、組織、教義や教育方針の変化として表す。

## 9.4 消失・再発見

教師が死んでも、弟子や原典が残っていれば技法は継続する。知識が地域から失われても、世界から完全に消えたとは限らない。史料の紛失・劣化、読める人物の減少、組織の断絶を別の状態として保持し、再発見で何が回復したのかを記録する。

最小実装は、一技能の二つの型、教師一人、弟子二人、一つの原典から始める。教師の死後に片方の型が別地域へ残り、原典から再伝授される流れをテストする。

# 10. 人口・集落・文明の勃興と再編

## 10.1 社会の人口

`world.characters` にある物語上の人物だけを都市の全人口と見なさない。集落ごとに生活段階、仕事、文化・言語・宗教への所属を集約した `PopulationCohort` を保持する。多次元の組み合わせを過度に分割すると集団数が爆発するため、初期は行動に必要な区分のみ実体化し、少数集団の統合・分割規則を持たせる。[S04]

台帳では総人口と個別管理人数を整合させる。移住は出発元から移動中へ、到着後に移住先へ移す。人物の死や出生を、個人イベントと集約人口の双方で別々に抽選しない。

## 10.2 集落の存続条件

集落は食料・水・住居・生産設備・交通・安全・運営組織などの状態を持つ。人口容量は固定の地点数倍率だけでなく、設備と供給に応じて変化させる。容量超過は即座の人口削除ではなく、生活条件、移住圧、建設需要へ反映する。

初期人口維持の移民補助は、通常の人口動態とは別のシナリオ補助設定として残せる。補助で追加した人物は由来を記録し、出生による世代交代が成立した指標に混ぜない。人口率と出生間隔は暫定設定とし、異なる文化・種族を同じ時間比率で扱わない。

## 10.3 文明・国家・共同体

`CivilizationSphere` は技術、文字、制度、交易、宗教などを共有する広がり、`Polity` は政治的な組織、`Settlement` は生活の拠点とする。国家が分裂しても文明圏が残り、征服後も技術や祭礼が継承されることを許容する。

文明を一本道の段階や優劣スコアに固定しない。食料安定、物流接続、技能継承、記録能力、組織の継続などを別軸とし、魔法設備へ依存する都市と自給性の高い地域を異なる形で表現する。現在の文明ラベルは、実体状態の要約投影として段階的に位置づけ直す。[S11]

## 10.4 勃興・安定・衰退・再編

変化は、条件が一定期間続いた場合に評価する。余剰生産と接続性が維持されれば集住や専門化の候補が増え、孤立や維持資源の不足が続けば人口流出や制度縮小につながる。閾値の出入りだけで毎期反転しないよう、開始条件、回復条件、最小継続期間を別に持つ。

すべての文明を強制的に崩壊させない。安定、変容、吸収、分裂、拠点移転、部分的な技術喪失を別の結果にする。衰退しても全知識と全文化が消える処理にはせず、移住先、遺物、教育、史料に何が残るかを計算する。

## 10.5 受け入れ条件

人口台帳が保存前後で一致し、移動中人口が二重計上されず、個人の死が二回差し引かれないことを必須とする。供給改善が持続すれば回復可能であること、一国の崩壊が無関係な言語や宗教の削除にならないこと、移民補助と自然な継承を別に計測できることを確認する。

# 11. 経済・物流・複数のネットワーク

## 11.1 初期経済の範囲

経済は、既存の繁栄・交通・道路状態の数値だけでなく、少数品目の在庫、生産、消費、輸送から作る。[S04] 初期品目は食料、建設資材、鉱石、道具、魔法資源を候補とし、実際の最小試作では三品目まで削減してよい。価格・税・貨幣・借入の精密化は後続とする。

生産は設備、労働、入力資源、知識、環境条件から決まる。消費は人口と活動の需要から決まり、不足時の代替、配給、活動縮小、移住圧を定義する。繁栄値は結果を圧縮した表示指標へ寄せ、実物の不足を別イベントで無条件に打ち消さない。

## 11.2 資源台帳と輸送

```text
期末在庫 = 期首在庫 + 生産 + 到着輸入
          - 消費 - 出発輸出 - 明示された損失

世界総量の変化 = 生産 - 消費 - 損失
                + 明示的な魔法生成 - 明示的な消滅
```

輸送は `Shipment` を持ち、出発時に発地在庫から引き、輸送中資産へ移し、到着時に着地へ加える。奪われた品は別所有者へ移った資産、破壊された品は損失とする。到着処理は冪等で、一便が二度在庫へ加わらない。

物流の必要最小条件は経路の接続、容量、所要時間、通行許可、危険、維持状態である。道の封鎖で瞬間的に世界中の在庫を変更せず、新規出荷と進行中の便の再計画へ影響させる。

## 11.3 割当と価格

各経済期間の開始状態から供給・需要を集計し、安定した順序または一括計画で出荷を割り当てる。更新順が先の集落だけ全資源を取得する偏りを避ける。価格を導入する場合は不足と余剰から緩やかに更新し、一期間の揺れで無限の振動を作らない。

物流計画の全面最適化は初期必須としない。近い供給先からの簡単な割当でも、量・容量・期間の整合を守る。経済ルールは国や文化ごとの共有・市場・組織配給を将来差し替えられる入口にし、最初から一種類の商取引だけを社会全体の法則にしない。

## 11.4 ネットワークの重ね合わせ

道路・海路・転移拠点は物理的な到達可能性を共有するが、物資、人、軍、噂、巡礼、技術伝授、言語接触は別の流量を持つ。魔法通信が届いても食料が届くとは限らず、封鎖下でも特定の使節が通行する例外を条件として表現できる。

接触量は言語や宗教の普及入力に使えるが、輸送一件で文化全体を変えない。期間集計、距離、利用主体、継続性を反映する。因果を表示する場合は「交易再開による接触増加」と「言語上の変化」を間にある状態も含めてつなぐ。

## 11.5 冒険との循環

魔物排除による通行再開、護衛による損失軽減、遺跡の修復による生産設備復帰を、実際の経路・設備状態へ反映する。依頼は不足や危険の原因から作り、報酬の支払い能力と所有元を持たせる。無制限の報酬生成はしない。

検証では、閉鎖→不足→代替経路→回復を固定条件で追い、総量、到着順序、襲撃時の損失、途中保存の一致を確認する。経済の成功を単に繁栄スコアが上がったことではなく、供給と生活が回復したことで判定する。

# 12. 宗教・儀礼・暦

## 12.1 宗教の四層

宗教は、世界に実在する超自然的なもの、信徒が語る教義・伝承、運営する組織、日々の実践に分ける。神が実在する世界でも教義がすべて正しいとは限らず、異なる宗派が同じ現象を別に解釈できる。特定の信仰を持つことをエンジン上の正解や能力の優劣に変換しない。

`FaithDefinition` は教義と儀礼の初期定義、`ReligiousCommunity` は実際の信徒と使用域、宗教組織は資産・構成員・拠点・継承規則を持つ。宗教と国家・文化を一対一に固定しない。現行の文化・勢力・用語の基盤から、本格的な宗教状態は新設する領域である。[S03]

## 12.2 日常的な役割

寺院や教団は、婚姻の承認、教育、記録保存、葬送、救護、旅人の保護、祭礼、巡礼に関与する。何を担うかは宗教・組織ごとの設定とする。宗教施設が失われた結果は信仰値だけでなく、サービス、史料、教員、救護容量、交通の変化として表す。

改宗や宗派分裂は、個人の経験、組織の継承、教義の対立、聖地の喪失、儀礼や奇跡の解釈などの条件から起こす。集団全体が一事件で一斉に変わる処理は、明示的な特殊シナリオ以外では標準にしない。

## 12.3 暦と記念行事

文化は異なる暦・年号を使え、同じ出来事を別の日付で記録できる。内部時刻は共通とし、記録時の暦IDと表記を保持する。改暦で過去の日付を上書きせず、必要な場合は現在暦への換算を併記する。[S13]

記念行事は、元の事件、主催共同体、周期、会場、必要資源、社会的効果を持つ。英雄の追悼、開通記念、収穫、巡礼などが、移動・出会い・交易・教育を生む。全死亡を祭礼化せず、共同体が維持する理由と能力を持つ場合だけ継続する。

## 12.4 言語との関係

典礼語、祈祷文、誓約文、年代記は特定の言語段階や表記を保存する。日常語の変化だけで儀礼文を更新せず、改革や翻訳運動を別イベントとする。宗教組織の教育活動が古語知識を維持し、制度の断絶が読解可能性へ影響する。

受け入れ条件は、宗教上の主張と実際の魔法現象が混同されず、制度の承認と個人の信仰が独立に変わり、改暦後も同じ物理期限が保持されることとする。

# 13. 魔法の世界法則と魔法文明

## 13.1 魔法法則の定義

`MagicLawSet` は、可能な作用、前提、資源、時間、範囲、容量、失敗条件、維持条件を定義する。戦闘呪文の効果と、世界の生産・治療・移動・通信・封印への作用は、共通の能力概念を持ちつつ別の実行契約にする。[S12]

魔法が強力であること自体を制限しない。ただし、無制限に使える能力を入れた場合は、その社会的帰結を設計する。食料生成があるなら通常農業の役割が変わり、転移が普及すれば物流の形が変わる。後から例外で帳尻を合わせず、作者設定として可視化する。

## 13.2 作用と代償

| 作用例 | 条件の例 | 世界への接続 |
|---|---|---|
| 治療 | 術者、施設、時間、処理容量、資源 | 生存、労働復帰、救護組織の役割 |
| 転移 | 拠点、容量、対象、維持資源 | 物流と移動、封鎖時の代替手段 |
| 生成・変成 | 入力または明示的な生成法則 | 資源台帳、産業、希少性 |
| 通信 | 距離・拠点・受信能力 | 噂、軍の連絡、共同体接触 |
| 結界・封印 | 設備、技法、継承者、維持条件 | 安全、ダンジョン発生源、文明の存続 |

代償の種類と強さは未決定であり、表は仕様候補である。魔法による生成・消滅は台帳上の明示トランザクションにし、資源保存則の例外を見えなくしない。

## 13.3 魔法文明の維持と脆弱性

魔法都市は、結界、水供給、転移、記録、治療などの設備へ依存し得る。設備には所有者、運営者、必要な技法、資源、保守期限がある。資源が届かない、技法の継承が失われる、制御拠点が奪われるなどの条件から劣化する。

言語の変化そのものを設備破壊の原因にせず、古い記録を理解し維持できる人と制度が失われたことを危機として扱う。特定の発声が魔法効果そのものを左右する世界設定を入れる場合は、その対応を独立した法則にし、翻訳表示と混同しない。

## 13.4 発見と検証

新しい技法の発見には、前提知識、実験または史料、必要資源、失敗時の結果を持たせる。噂に書かれた呪文を読んだだけで能力定義を任意に生成・実行しない。作者が許可した効果の組み合わせを検証し、強度や作用範囲の上限を持たせる。

受け入れ条件は、消耗資源と設備状態が一度だけ変化し、言語の表示変更が魔法結果を変えず、維持が停止すれば予告された経路で機能が低下することとする。

# 14. 地点・ダンジョン・遺跡・歴史層

## 14.1 起源と現在の危険を分離する

遺跡は過去の用途や文明の痕跡、ダンジョンは現在の探索構造と脅威を表す。遺跡だが安全な施設、新しく発生した魔法迷宮、遺跡かつ魔物の拠点、攻略後に再利用される城塞を同じモデル上で扱えるようにする。`region_type` 一つで起源と現在用途を兼用しない。

`SiteHistoryLayer` は成立時刻、用途、住民または運営組織、文化・言語、建設・放棄・破壊の原因を持つ。地形、施設、社会的用途を分け、一時的に廃墟になっても地点IDと過去の記録を消さない。

## 14.2 ダンジョンの構造

初期の探索単位は、入口、区画、接続、危険、封鎖、資源、目標からなる小さなグラフとする。手作業の区画定義と生成区画を併用でき、各区画は戦闘以外に調査、解読、修復、交渉、運搬などの解決方法を持てる。

`ThreatSource` は魔物の流入、魔力蓄積、封印崩壊、敵対組織など、脅威を供給する原因を持つ。敵を倒した数と、原因を止めたかを区別する。どこから危険が補充されるか不明のまま、時間経過で無条件にリセットしない。

## 14.3 探索・攻略・維持

探索進捗は知識、攻略度は現在対処した障害、再増殖は供給源と時間による再発を表す。既存の攻略度・再増殖値は、初期の集約表示として生かし、後の探索条件へ接続する。[S14]

目的によって成果を変える。偵察は情報、討伐は脅威の減少、救助は人物と関係、発掘は史料・遺物、修復は設備と経済の回復へ作用する。「無事に帰った」という結末だけで全地点へ同じ攻略ボーナスを与えない。

維持する組織や費用がある場合、安全化の持続性が変わる。発生源を停止した区画は再増殖を止め、入口だけ制圧した場合は奥から戻り得る。危険度計算の責任を一か所へ集め、土地への事件影響と冒険開始時の補正を二重加算しない。

## 14.4 遺跡の再利用と古道

旧水道の修復が供給を戻し、廃砦の再建が物流を守り、神殿の再開が教育と記録を回復する、といった接続を持つ。遺跡は報酬の箱だけでなく、文明の再興に使える設備として扱う。

古地図に記された道と、現在通行可能な経路は別データとする。史料に線があるだけで移動可能にしない。調査、障害除去、再整備によって現行ネットワークへ復帰する。経路の再発見は地点の旧名や言語史を使って推定できるが、唯一の正解手段にはしない。

## 14.5 受け入れ条件

同じ地点に複数時代の履歴を表示でき、攻略成果が危険・情報・生産の適切な対象へ返り、固有遺物が複製されず、供給源を停止した危険が理由なく復活しないことを確認する。再利用で過去の遺跡情報が削除されないことも必須とする。

# 15. 冒険・パーティー・救助・成果

## 15.1 目的・進め方・撤退条件

現行の方針は目的と進め方が混在し、一部の選択は文章以外の効果が同じである。[S14] 新規冒険は目的、行程上の進め方、撤退規則の三軸で構成する。

| 軸 | 初期候補 | 変えるもの |
|---|---|---|
| 目的 | 偵察、救助、探索、討伐、運搬、修復 | 成功条件、必要能力、成果 |
| 進め方 | 慎重、標準、急行 | 所要時間、発見機会、危険、消耗 |
| 撤退条件 | 目的達成、重傷者、補給不足、期限 | どの状態で帰還へ移るか |

救助には救助対象、修復には修復する設備、運搬には実際の荷物を持たせる。旧 `rescue` 方針の保存データに存在しない対象を後付けしない。旧冒険は互換ルールで完了させるか、対象を要しない旧目的として読み込む。

## 15.2 個別の進行予定

各冒険は `next_step_tick`、区間の経路、残り所要時間、物資、期限を持つ。進行回数を世界共通の抽選だけで決める方式から、個別の行程に基づく予定へ移す。ランダム性は遅延や遭遇に用い、出発したのに長期間いつまでも到着しないだけの待機を減らす。

出発後の経路封鎖、目的地の占領、対象の移動・救助・死亡で計画を再評価する。現在地、移動中の区間、居住地、冒険の出発地を分け、同席者判定や救助対象検索が同じ場所を参照するようにする。

## 15.3 選択の実効性

慎重な進行は事前の危険発見や対処に有利だが、時間と消費が増える。急行は期限に有利だが見落としや遭遇時の不利が増える。撤退は生存と持ち帰りを重視する代わりに未達成の機会を失う。固定の有利不利ではなく、目的と状況によって選ぶ理由を作る。

効果の持続範囲を明示し、「一区間だけ」「冒険終了まで」の違いを保存する。一回あたりの危険だけでなく、総行程の累積危険と補給を比較してバランスを検査する。UIには実際のモデルに対応する理由を示し、未測定の成功率を断定的な数字で出さない。

## 15.4 パーティーの役割

役割は前衛、斥候、知識、救護、交渉、運搬などを候補とする。職業名だけで固定せず、現在能力と技能から適性を評価する。同能力の三人を単純平均して一人と同じとする方式を改め、主担当の能力と補助の減衰効果を使う。

人数には補給、移動、連携、収益分配などの費用を持たせ、人数が多いほど必ず最善にはしない。同行者の選定には同じ場所、参加意思、健康、関係、目的を反映する。救護役が実際に悪化を抑え、斥候が経路・遭遇へ作用することを検証する。

## 15.5 救助の一周

負傷または行方不明の発生から、情報到達、目的生成、参加判断、進行、救助または失敗、帰還、関係・評判・記憶の更新までつなぐ。対象が既に死亡・帰還・別隊に救助されていれば、目的は更新または失効する。

救助成功を単なるフラグではなく、対象の健康・現在地・所属冒険、実行者との関係、投入した資源に反映する。途中で救助された人物が、帰還処理の古い負傷値によって再び死亡しないようにする。

## 15.6 構造化された成果

各ステップは `AdventureStepResult` を返し、種別、役割付き参加者、場所、変更内容、原因、表示材料を持つ。到着・偵察・発見・負傷・救助・死亡・帰還を文字列や前後状態から推測して分類しない。同行者のIDを正規イベントに含め、共有経験が個人史と関係へ届くようにする。[S15]

成果の適用、イベント登録、目的更新を一つの論理単位にする。報酬は、資産、技法、情報、評判、関係、設備など実在する対象へ返し、ログにだけ戦利品が増えて終わらないようにする。

# 16. 戦闘・負傷・死亡

## 16.1 戦闘の位置づけ

戦闘は人物史や世界変化の一部であり、独立した最適装備ゲームだけへ寄せない。通常戦闘、冒険の危険遭遇、勢力規模の衝突は共通の解決部品を利用できるが、損耗や目的は各領域で定義する。既存の副作用なしで結果を返す戦闘解決を生かす。[S12]

## 16.2 勝敗と終了理由

戦闘耐久値が0になった場合は、その決着を最優先する。最大攻防回数に達して双方が戦闘可能な場合のみ、判定・離脱・引き分けの規則を使う。基礎戦闘力を加えた後段の総合点で、先に戦闘不能になった人物を勝者へ戻さない。

戦闘不能と人物の死亡は同義にしない。勝敗結果には終了理由、参加者の最終状態、与えた被害、決定的な行動を含める。防御技能は意図した防御処理へ使い、最高レベル技能というだけで攻撃に変換しない。技能同点時の優先順位も明示する。

## 16.3 遭遇・対処・被害の分離

冒険の危険は、遭遇したか、どう対処したか、結果として何を失ったかの三段階に分ける。負傷する分岐を確定してから戦闘ログを添える方式を改め、勝利・被害軽減・回避・撤退が最終的な負傷へ作用するようにする。

勝者が必ず無傷である必要はないが、被害を受けずに対処した結果が無条件の負傷へ変換されないことを保証する。強い技能や適切な役割が、集計上も被害を減らすか検証する。

## 16.4 健康状態の正本

現在健康は `Character` を正本とする。`AdventureRun` は過去の負傷記録や対象IDを持てるが、並行する現在状態として生死を決めない。救助・治療・自然回復・悪化を同じ健康変更入口へ統一する。

帰還はその時点の人物状態を読む。移動中の死亡が必要なら健康期限の処理として起こし、帰還したことを理由に過去の瀕死状態を再適用しない。死亡後処理は共通関数で一度だけ行い、配偶者関係、冒険、資産、継承、通知、碑文生成の二重処理を防ぐ。[S16]

## 16.5 必須回帰テスト

戦闘不能者の判定勝ち防止、防御技能の処理、同点の決定性、勝利と負傷の整合、非リーダーの被害記録、救助後の帰還、同日健康期限、死亡後処理の冪等性を必須とする。旧戦闘テストの単なる件数維持ではなく、ゲーム上の意味を確認する。

# 17. 遺物・世界の記憶・噂・伝承

## 17.1 固有遺物

通常消耗品は在庫として、物語上重要な品は `Artifact` として個別IDを持たせる。製作者、作成年代、刻文、材料、用途、所有者、保管場所、由来の記録を保持する。盗難、譲渡、相続、紛失、再発見は同じ品の履歴であり、新しい複製を生成しない。

刻まれた言語と文字は作成時点で固定し、現在語の変更で刻印を変えない。真贋、所有権の主張、信じられている由来は、実際の製造履歴・所有履歴と分ける。価値は戦闘力以外に、通行証、原典、形見、制度上の証拠、交渉材料にも設定できる。

## 17.2 世界の記憶

既存の痕跡、碑文、別名、NarrativeContextを、共同体が何を残すかという過程へ伸ばす。[S17] 記念物は人物や事件、作成者、維持主体、作成時の主張を持つ。すべての死を英雄化せず、目撃者、資源、組織の関心、継承者によって残り方が変わる。

同じ出来事から、家族の記憶、支配組織の顕彰、別共同体の批判的記録が生まれ得る。どれかを世界の事実へ上書きせず、異なる解釈として並存させる。

## 17.3 噂と認識

既存Rumorの対象、確度、聞き手、偏り、歪曲、関連参照を生かし、主張の構造と伝播元を追加する。[S18] 噂は文章ではなく、道が通れない、人物が生きている、遺物が本物だ等の主張を人物の判断へ渡す。

同じ発信源の複製を独立した証言として数えない。`provenance_chain` または共通の発信IDを持ち、複数の伝聞と独立した観測を区別する。訂正は、訂正情報を知った人物・共同体の認識を更新し、世界中の信念を一括で置き換えない。

## 17.4 誤情報にも結果を持たせる

誤った封鎖情報を信じた商人が迂回する場合、実際の道路状態は変わらず、行動の選択だけが変わる。その結果の輸送先・交易量・接触量は現実の世界状態へ反映する。正確に翻訳された誤情報と、正しい情報の誤訳も分ける。

プレイヤーに見せる確度は観察者の知識に基づく。内部の真偽を常にUIへ露出する全知モードと、当事者の判断を表す個人モードを区別する。

## 17.5 伝承と神話

`TraditionRecord` は元の出来事、語られる主張、伝える共同体、媒体、版、前の伝承への参照を持つ。歌、碑文、祭礼、地名、英雄譚へ表現を変えられるが、新しい文章を生成するたびに事実を追加しない。

伝承が後の組織・誓約・巡礼・命名へ影響して循環が成立する。世界内の忘却は、誰が知っているか、媒体が残っているかの変化として扱う。プログラムのメモリ削減によって、正本の因果や語源が消えることと混同しない。

## 17.6 受け入れ条件

同一遺物の所有者が同時に二人へ確定しないこと、誤情報が物理的事実を直接変えないこと、噂の複製だけで根拠が無制限に増えないこと、二つの共同体の異説を同時に表示できること、伝承の版と元の事件を追跡できることを確認する。

# 18. 勢力・制度・戦争と長期アーク

## 18.1 制度の成立と継続

家、学派、宗教組織、都市の運営組織、国家は、目的、構成員、拠点、資源、意思決定、継承規則を持つ。人物が活動を続けることで組織が成立する経路と、初期設定で組織を置く経路を併用する。

創設者の死後も組織が続くか、分裂するか、解散するかは資源・構成員・継承の条件で決める。名前が残っているだけの組織と、実際に活動している組織を区別する。組織への所属は文化・言語・信仰の自動変更を意味しない。

## 18.2 WorldArcの役割

`WorldArc` は長期過程の段階、時刻、対象、原因・関連イベントを結ぶ共通の枠として利用する。[S19] 戦争、再建、宗派分裂、交易拠点の成立等を関連付けられるが、固有のルールと状態を無制限に `metadata` へ詰め込まない。領域ごとの型付き状態を参照する。

アークは脚本の次ページを読むだけの仕組みにせず、現在の前提、参加者の行動、資源、外部事件から遷移する。関連があるからといって直前の全イベントを原因参照に入れない。

## 18.3 戦争の最小モデル

戦争は対立する組織、目的、対象拠点、活動する部隊または集約戦力、補給、損耗、疲弊を持つ。毎回その場で同じ軍勢を作るだけではなく、戦闘結果が継戦能力に残るようにする。最初は少数の戦力・補給項目に絞る。

支配地の変化、交易路の封鎖、住民の移動、宗教施設や教育拠点への影響は同じ世界変更の入口へ流す。戦争終了は一様な乱数だけでなく、目的達成、継戦不能、和平、内部再編などの条件を持たせる。敗戦で勢力の文化や言語を一括削除しない。

## 18.4 受け入れ条件

組織の継承が一貫し、同じ戦力が戦闘ごとに初期化されず、補給遮断が実際の行動へ作用し、戦争の終結後も住民・物流・制度の余波が残ることを検証する。政治的な呼称や敵味方の評価は、作中の主体による主張として区別する。

# 19. 魔王・勇者・大規模シナリオ

## 19.1 シナリオの基本契約

大規模シナリオは、世界の状態を読み、役割を実体へ結び付け、段階的な危機と対策を生む長期過程とする。固定の勝利者と結末を強制せず、早期解決、封印、討伐、隔離、撤退、支配の変化、敗北後の継続を許容する。

`ScenarioDefinition` は作者が記述する開始条件、役割、段階、行動、終結、余波の定義である。`ScenarioInstance` は今回の対象地点、人物、組織、資源、進行履歴を持つ。既存 `WorldArc` を進行の共通枠とし、シナリオ固有の状態は別型にする。

## 19.2 発生経路

| 型 | 主な成立条件 | 世界との接続 |
|---|---|---|
| 封印崩壊型 | 設備・技法・資源・継承の喪失 | 遺跡、教育、物流、宗教、魔法維持 |
| 勢力形成型 | ある存在が支持・拠点・資源を蓄積 | 組織、経済、戦争、住民の反応 |
| 外的到来型 | 作者が定義した世界法則や周期 | 暦上の予告、超自然条件、対策の準備 |
| 明示起動型 | シナリオ選択または開発操作 | 通常の自然発生と区別した出所を保存 |

すべてを社会条件から発生させる必要はない。外的到来を使う場合も、その原因を世界法則として明示する。演出の都合で資源や人物の死を無言で取り消すことは標準動作にしない。

## 19.3 シナリオ状態と遷移

| 段階 | 主な状態 | 遷移・介入の例 |
|---|---|---|
| 潜在 | 発生条件と未観測の兆候 | 保守・調査で危機の蓄積を抑える |
| 前兆 | 局地異変、情報、初期被害 | 調査、避難準備、封印修復 |
| 顕在化 | 脅威主体・拠点・支持勢力 | 抵抗組織、補給路、情報の争奪 |
| 拡大 | 支配・資源・被害の増大 | 拠点奪還、資源遮断、連合形成 |
| 対抗 | 複数の解決計画 | 討伐、再封印、隔離、交渉、避難 |
| 終結 | 選ばれた結果と未解決要因 | 早期解決や敗北を含めて確定する |
| 余波 | 人口・制度・土地・伝承の再編 | 復興、祭礼、改名、継承、再発条件 |

すべての事例が全段階を通る必要はない。遷移は前提条件と確定した結果を用い、段階が上がるほど必ず敵が強くなるだけの一本調子にしない。

## 19.4 役割の解決

シナリオは魔王、対抗者、支援者、情報保持者、封印技術者、避難先などの役割を要求できる。役割は条件に合う既存実体から選び、いない場合は待機、代替手段、集約住民からの具体化、または成立不能を返す。結果を成立させるためだけに人物や遺物を無制限に生成しない。

役割を持つ人物が死亡・辞退・移住した場合は再評価する。再評価の方針を定義に持たせ、同じ人物を復活させて穴埋めしない。必要な古文書や鍵は原則として地点の履歴や前史と整合する資産を使い、後から配置する場合は配置の出所を明示する。

## 19.5 勇者の三つの成立

超自然的な選定、組織による認定、行動による評判を別状態にする。三つが同じ人物に重なることも、異なる人物に分かれることもできる。称号、潜在能力、実際の能力、支援資源を一つの `is_hero` フラグへまとめない。

出生時の印や使命を設定しても、人物の現在の生活段階と活動能力は通常の規則に従う。成長前に危機が進む場合、既存の熟練者や組織が対応する。出生・認定・初の実績・称号継承を別イベントとして記録する。

勇者が死亡した場合、別候補、集団による対策、退避、敗北後の再建などの経路を持つ。特別な保護を設けるモードでは、内容と限界をルールセットに明示し、通常の生死モデルを秘密裏に変更しない。

## 19.6 脅威と対策の多軸化

魔王側は戦闘力だけでなく、拠点、供給源、協力者、移動可能性、魔法的条件を持つ。抵抗側は討伐以外に補給遮断、古い設備の修復、住民の避難、同盟交渉、情報確認で結果へ影響できる。

対策には必要資源・時間・担当・失敗の結果を持たせる。学者や商人や祭司が活躍する理由は、称賛文を追加することではなく、対策の成立条件に実際に必要であることから生む。ただし一人の固有職業がいなければ必ず詰む構造にはせず、異なる費用での代替を用意する。

## 19.7 余波と再発

終結後は被害人口、失われた設備、残存勢力、戦時の組織、功績、家の台頭、祭礼、改名、伝承を更新する。敵の撃破だけで世界を出現前の状態へ戻さない。再発は原因が残っている、維持が失われた等の条件を持ち、同じシナリオが即座に連続発生しない冷却期間を設ける。

シナリオの重なりは、同一資源・役割の競合を調停する。活動数の上限は世界生成・物語モードの設定として明示できるが、既に起きた因果を無言で破棄して枠を空けない。

## 19.8 記録と受け入れ条件

シナリオは通常のドメインコマンドを使って世界を変更し、独自の隠れた在庫や健康値を持たない。進行レコードには満たした条件、使用した根拠、消費資源、結果を保存する。

前兆での防止、勇者不在、勇者死亡、資料喪失、魔王拠点の早期喪失、対策失敗、避難成功、敗北後継続、同時シナリオの競合、余波の保存再生を検証する。どの分岐も必ず勝利へ誘導せず、どの分岐でも参照や処理が壊れないことを合格条件にする。

# 20. 地理生成・前史生成・年代の接続

## 20.1 地理の足場

既存の地形生成PoCは決定性と検査可能性を重視し、地点候補と選定理由を持つ。[S20] まずは生成結果を本体へ安全に取り込む契約を定義し、地形の複雑さより、到達可能性、生活可能な拠点、資源、歴史を保持する地点IDを優先する。

地形から集落の候補と経路を作り、供給・交通の条件を検査する。すべての候補に文明を配置せず、未開拓・放棄・聖域・危険地などの違いを残す。生成不成立の場合は理由を返し、無関係な地点へ無条件にワープさせて接続不足を隠さない。

## 20.2 前史の生成順序

```text
地理・資源・魔法条件
  → 初期共同体と祖語・文化
  → 移住・接触・分裂・集落の成立
  → 組織・宗教・技術・交易の発展
  → 戦争・災害・再編・放棄
  → 遺跡・古名・史料・伝承の残存
  → 開始時点の人物と集約人口
```

前史は年代記上の主要転換点を生成する。日単位で何千年も回すことを初期必須にしない。各転換点の前提・結果は同じ型付きの検証規則を用い、粗い生成だから保存や系譜が矛盾してよいとはしない。

## 20.3 美的な作者制約

作者は、言語の響き、古名が残る地域、魔法設備への依存度、文明の数、主要な前史、開始時の危機を制約として指定できる。自動生成は制約の範囲内で展開し、作者が置いた固有設定を勝手に上書きしない。

生成済みの過去と、未確定の背景候補は区別する。後から細部を具体化するときは既存制約を満たす候補に限定し、既に観察された歴史を別の歴史へ置き換えない。

## 20.4 引き継ぎの検査

プレイ開始時点で、在庫・人口・物品所有・系譜・言語段階・制度の有効期間・シナリオ状態を確定する。前史に存在する人物は開始年齢と生存状態が矛盾しないようにし、未知情報は未知と明記する。

同じ生成シードとルール版で同じ前史を作れ、生成後の保存読込で初日の状態が変わらないことを確認する。前史の全文章を保存する必要はないが、現在状態の根拠となる確定イベントと基点を保護する。

# 21. 観察UI・個人モード・アプリケーション境界

## 21.1 画面の中心

中心画面は、現在の重要な変化、注目人物、進行中の過程、実行できる行動へ答えるダッシュボードとする。既存のダッシュボード・年報・噂・地図・冒険画面は再利用し、別画面を大量追加する前に対象間の遷移を整える。[S21]

地図には現在地、目的地、通行可否、輸送・巡礼などの流れ、未確認情報、歴史層を切り替えて表示する。全情報を常時重ねて読めなくしない。古名から現在地点、人物から家、家から婚姻、事件から言語変化へ移動できるようにする。

## 21.2 言語史の閲覧

語族・系統・段階、同源語比較、語源、借用、使用共同体、古語・文字、名前の履歴を閲覧できる。系統の線と借用の線は見た目も意味も区別する。古文書には作成時点の文字列と、現在視点の読解を分けて表示する。

語形の変化を一語ずつ追える詳細表示と、地域の言語使用がどう変わったかを見る年表を用意する。過去から現在へ移動しても、同じ語・地点の参照が維持されることを優先する。

## 21.3 自動進行と通知

自動進行は、意味のある選択、注目対象の新しい危機、目的の達成、期限、指定期間まで進む。既に確認した同じ警告で無限に停止しない。必須の保留選択、助言としての警告、通知済み状態を分ける。

停止後は、対象を見るだけでなく、救助の計画、資源の割当、方針の変更、調査、委任、見送りへつなげる。介入に必要な時間と主体を示す。注目対象が増えたこと自体で世界の事件頻度を増やさない。

## 21.4 コマンドとビュー

UIからはJSON互換のコマンドを送り、IDと型付きの表示モデルを受け取る。生のWorldやCharacterを変更可能な状態でUIへ渡すことを標準契約にしない。既存 `FantasyAppService` の境界を拡張する。[S21]

コマンドには `command_id`、必要なら `expected_revision` を付け、再送による二重適用と古い画面からの更新を検出する。日数や実行件数には上限と中断点を持たせる。長い進行は一つの不可分な処理にせず、整合性の取れた区切りで結果を返す。

## 21.5 表現とアクセシビリティ

正式名・旧名・翻訳・読み仮名を区別し、表示言語変更で世界内の名前を変更しない。状態を色だけで表さず、文字と凡例を併用する。全知視点と個人視点、事実と未確認情報は常に分かるようにする。

読み物としての文章と、検証可能な数値・根拠を両立する。推定確率が未校正なら、断定的なパーセントではなく要因と不確実性を示す。詳細情報を畳んでも、判断に不可欠な期限や対象が隠れないようにする。

# 22. 保存・移行・履歴保持・再現性

## 22.1 保存の外枠

保存は `schema_version`、`ruleset_version`、`world_id`、共通時刻と旧時刻への対応、設定の版とダイジェスト、領域状態、正規履歴、必要な乱数状態、進行中の予定を持つ。派生キャッシュは保存可能でも、正本の代わりにしない。複数の正本候補がある場合の優先順位を領域ごとに定義する。

現行の一時ファイルへの書き込みと置換による保存方式は維持する。[S22] 保存直前に参照・重複ID・型・上限を検査し、保存失敗時に以前のファイルを破壊しない。読み込みも一時的な世界として完了させ、成功後にUI言語など外部状態へ反映する。

## 22.2 三つの互換性

旧ファイルを読める読み込み互換、同じルール版で中断前後が一致する継続の再現性、異なる旧ルール版と同じ未来を再現する旧ルール再生を区別する。前二者を優先し、過去すべての不具合まで保存する無制限な旧ルール互換は要求しない。

ルール変更後は未来が変わる可能性を記録し、どの時点から新ルールを使ったかを保存する。旧進行中の冒険を互換モードで完了させる場合、その対象と終了条件を明記する。

## 22.3 領域ごとの復元方針

| 領域 | 正本 | 復元・競合時の方針 |
|---|---|---|
| 人物・在庫・組織 | 検証済み領域スナップショット | 事実履歴との整合検査。全履歴再生を暗黙に要求しない |
| 言語段階・語源 | 基点＋順序付きの確定変化 | 履歴からキャッシュを再構築し、旧規則版を尊重する |
| 名称・碑文・史料 | 命名・作成時の固定内容と変更履歴 | 現在の生成候補から再抽選しない |
| 文明・時代投影 | 採用済みADRで定義した履歴・基点 | 実験的ランタイム値を無条件に優先しない |
| 婚姻・認定 | 成立時の制度版と承認履歴 | 現行制度だけで過去を無効化しない |
| 通知・地図・索引 | 派生情報 | 不整合なら破棄して再生成する |

現行の文明スコア復元は、記録された変更を再構築へ反映する修正候補である。修正では記録された制限後の値を使い、履歴圧縮後にも必要な根拠が残ることを検査する。ランタイム保存を追加する場合は既存の保存方針を改定する。[S11]

## 22.4 履歴保持とチェックポイント

表示上重要な履歴と、現在状態の復元に不可欠な履歴を区別する。語源、制度の版、進行中シナリオ、親族、所有権、誓約などの根拠は、単純な重要度順で落とさない。既存の参照閉包による保持を足場に、領域ごとの必要根拠集合を追加する。[S22]

チェックポイントは、対象領域、適用済みの最後の順序、ルール版、状態ダイジェスト、以後の履歴への参照を持つ。基となった詳細履歴を削除する場合、そのチェックポイントは正本の一部となる。単なる高速化キャッシュと呼んで破棄可能にしない。

物語上の忘却は、人物や共同体の知識・媒体の劣化として表す。容量削減で事実を削る処理とは分ける。長期保存の目標件数を超えた場合は警告と計測を行い、整合性より件数を優先しない。

## 22.5 主な移行

旧 `spouse_id` は矛盾のない場合に旧形式の婚姻レコードへ移すが、制度や承認主体が不明なら不明として保存する。旧の家族タグから明確な親子関係だけを移し、`family` 一般から系譜を推測しない。

旧の語彙文字列は出自未確定の語として保存し、意味のない語へ新しい意味を捏造しない。旧地名は固定表面形を保持し、新規生成だけ意味付き方式に移行できる。旧の救助方針は対象のない旧方針として扱い、架空の救助対象を作らない。

旧人物の年齢は元の暦条件を使って一度だけ新時刻と生活段階へ対応付け、移行で余分に老化させない。既存の資源を新台帳へ移す場合、由来不明の初期資産として明示する。

## 22.6 読み込みの防御

型、列挙値、範囲、参照先、循環、重複、サイズ、予期しない属性を検査する。季節補正の復元では `hasattr` だけで任意属性を受理せず、許可された数値項目に限定する。エラーはフィールドの場所と理由を返し、部分的に読み込まれた世界を活動状態にしない。

# 23. 開発基盤・拡張性・非機能要件

## 23.1 モジュール配置

既存のパッケージ構成を維持し、`culture/`、`household/`、`economy/`、`religion/`、`scenario/` 等は責務が具体化した段階で追加する。型を増やすこと自体を成果とせず、生成・更新・保存・表示・テストの一周が完成する単位で導入する。

言語は `language/` と `world_language/`、地点の変化は `world_change/`、長期過程は `world_arc/`、UI入口は `app/` を生かす。共通化するのはID、時刻、参照、変更の検証、保存契約であり、婚姻・文法・戦争を同じ万能状態機械へ無理に統合しない。

## 23.2 型と更新境界

外部入力と保存データ用の型、ドメイン値、表示用モデルを区別する。重要な列挙やIDは単なる任意文字列の混用を減らす。変更前のリビジョンを検査し、無効な状態から有効な結果を黙って作らない。

段階的に型検査対象を広げる際は、永続化、日次進行、文化規則、経済台帳、言語段階を優先する。循環インポートやUI依存の混入は既存のアーキテクチャ検査へ追加し、手動の注意だけに頼らない。[S23]

## 23.3 作者用コンテンツ

設定バンドルには、文化・婚姻規則、種族の成長、資源・設備、宗教・儀礼、魔法法則、言語、遺跡テンプレート、シナリオ定義を段階的に追加する。参照の検証、差分表示、サンプル生成、固定シード実行を用意し、作者が規則の効果を確認できるようにする。

初期版のModは宣言的データに限定する。条件式は許可された小さな評価器を通し、設定ファイルから任意のPythonを実行しない。展開サイズ、再帰、候補数、生成試行回数に上限を設け、無効な定義は説明付きで拒否する。

## 23.4 性能と成長制御

毎日の人物×全履歴走査や、全語彙の再生成を避け、対象・地点・役割・言語段階ごとの索引を使用する。派生キャッシュには入力依存と失効条件を明記し、不要な過去年度分を無限保持しない。

初期性能基準は計測用の仮置きとし、実測した時間やメモリと混同しない。固定シード・世界規模・実行年数・実行環境をセットで記録し、日あたり時間、保存容量、主要エンティティ数、保護履歴件数、キャッシュ数を比較する。

## 23.5 オフラインと表示

基本計算と保存・生成はオフラインで成立させる。将来の外部文章生成は任意機能とし、事実・語源・イベントの確定に必須としない。外部文章は承認済みの意味構造を表現する範囲に限定し、生成文が新しい世界事実を追加しない。

端末バックエンドや将来のUIは差し替え可能にし、世界データの正本を移動しない。描画性能の改善とゲーム計算の改善は別の計測対象とする。

# 24. 検証仕様と品質指標

## 24.1 検証の階層

単体テストは規則の意味、統合テストは領域間の接続、プロパティテストは不変条件、固定シナリオは体験の一周、長期統計は人口・経済・事件の偏りを確認する。既存の最低件数を使った世界健全性テストは残すが、面白さや完全なバランスを証明するものとは扱わない。[S24]

## 24.2 必須の不変条件

| テストID | 不変条件 | 代表的な検査 |
|---|---|---|
| T-01 | 通常処理で生死と健康が競合しない | 救助後帰還、非リーダー死亡、二重後処理 |
| T-02 | 戦闘経過と決着が一致する | 先に戦闘不能となった側の判定勝ちを防ぐ |
| T-03 | 婚姻と成長・活動を混同しない | 文化別成立、若年関係、独立した活動適格性 |
| T-04 | 文化規則の版が歴史に残る | 制度改定前後、主体ごとの認定、不明親族 |
| T-05 | 言語の分岐と適用順が安定する | 分岐後祖先変化、借用時期、語形の二重適用 |
| T-06 | 名称と史料が再抽選されない | 語彙追加、表記変更、UI言語変更 |
| T-07 | 人口と資源が二重計上されない | 個人化、移住中、死亡、到着再送、略奪 |
| T-08 | 事実と認識を混同しない | 誤情報による迂回、独立証言、訂正伝播 |
| T-09 | 役割の欠損でシナリオが壊れない | 勇者死亡・辞退、資料喪失、代替対策 |
| T-10 | 保存と圧縮で未来の意味が変わらない | 同版の連続・分割・保存後進行の比較 |
| T-11 | 観察が世界を変えない | 全画面閲覧の有無、通知表示、翻訳 |
| T-12 | 過去の正本が勝手に変わらない | 前史細部化、旧データ移行、名称と制度 |
| T-13 | 成果が実際の後続状態へ返る | 攻略で危険低下、修復で物流復帰、教育で伝授 |
| T-14 | 更新が一度だけ適用される | 同一command_id、同一死亡・婚姻・出荷の再送 |

復活を許す魔法設定がある場合は、通常の死亡処理の取り消しではなく、前提を持った明示的な復活イベントとして別検証にする。初期版で未採用なら、死者を通常活動へ戻さない。

## 24.3 比較テスト

同じ保存状態から、一定日数を連続で進めた結果と、途中に保存・復元を挟んだ結果を比較する。比較対象は正規状態、主要履歴、予定、使用乱数であり、キャッシュ容量や表示時刻など非意味的な値を除外する。

履歴圧縮は、圧縮前後の現在状態の投影と、その後の継続結果を比較する。表面的に保存辞書が同じでも、保存されないランタイム状態が異ならないかを調べる。キャッシュあり・なしの計算結果も比較する。

無関係な定義追加で既存の生成結果が変わらないことを検査する。ただし、実際に交易・移住・接触で結び付いている領域の正当な相互作用まで禁止しない。独立性テストの前提を明示する。

## 24.4 バランスと体験の指標

人口では生存人数だけでなく、出生、移民、世代継承、年齢構成、背景人口と個別人物の一致を測る。経済では欠乏期間、回復時間、輸送成功率、損失、在庫発散を測る。冒険では目的別の達成、死亡、負傷、撤退、総所要時間を比較する。

言語では同源語の対応、言語内一貫性、派生の説明可能性、独自語の保持、命名安定性、語形衝突、無効生成、史料の読解可能性を測る。名前の一意性だけを最大化せず、同名が存在しても識別できることを確認する。

大規模シナリオでは発生理由、早期解決、各終結、役割の交代、被害、復興、再発を測る。特定の結末を常に保証することを成功指標にせず、条件による違いが出ることと世界が継続することを重視する。

## 24.5 CIと配布

通常のpytest、静的検査、依存境界検査に加え、作成したwheelをクリーンな環境へ通常インストールし、リポジトリ外から起動・設定読込・保存復元を確認する。UI追加依存あり・なしの経路も検証する。[S23]

長期統計は少数の固定シードだけで結論を出さず、目的別のシナリオ群と複数シードを用意する。実行時間が大きい試験は通常の開発ゲートと分離し、結果には対象コミット、環境、シード、ルール版を必ず付ける。

# 26. 統合シナリオと受け入れ仕様

## 26.1 シナリオA：古名と失われた通路

前提は、祖語から分かれた二つの言語、旧名を記した古地図、現在は別の公称を持つ峠、閉ざされた旧道とする。以下の語形は説明用の創作であり、特定作品や現行生成結果を表すものではない。

古地図の `Karum` と現地語の `Kharum` が同じ命名記録から派生し、現在の公称は政治的な改名として別に存在する。人物は語根、音変化、地形、証言を組み合わせて同じ場所だと推測する。語学に詳しくなくても、通訳や現地調査による代替を用意する。

受け入れ条件は、古地図の表面形が現在語更新で変わらないこと、語源が同じ地点IDへつながること、推測しただけでは道が通行可能にならないこと、調査・修復後に物流へ反映されること、すべてが保存後にも続くことである。

## 26.2 シナリオB：異文化間の婚姻と二地域の家

二文化は親族条件、婚姻成立の生活段階、承認主体、居住・継承規則が異なる。当人二人、両家、宗教組織を用意し、当人の意向と家の希望が完全には一致しない初期状態を置く。

成立した場合、婚姻記録には制度版と主体別承認が残り、居住と財産の取り決めが実際の世帯・台帳へ作用する。否認または拒否された場合は、制度上の事実と感情・家の関係が別々に変化する。若年の婚姻を含む設定でも、その人物の教育段階や遠征適格性は独立のままとする。

受け入れ条件は、文化を変えた比較実験で成立・承認が変わること、家の関係が物流や移住の選好に影響し得ること、言語の学習が養育・接触に基づくこと、制度改定で過去の記録が消えないことである。

## 26.3 シナリオC：救助・恩義・誓約・継承

冒険者が負傷し、知らせが町へ届く。関係の深い人物は救助を望み、プレイヤーは急行、準備、委任、見送りから判断する。所要時間と供給を実際に消費し、到着時の対象状態を確認する。

救助成功は健康、同行、帰還、関係、評判へ反映し、誓約を結ぶ場合は具体的な対象と履行条件を記録する。失敗なら死を二重処理せず、遺物と記憶が生存者へ残る。後世の家族や弟子は、義務を自動継承するのではなく、期待を受けて引受けを判断できる。

受け入れ条件は、戦闘・救助・帰還で健康が矛盾せず、同行者に共有履歴が残り、恩義が後の行動に使われ、元の事件から伝承まで因果が追えることである。

## 26.4 シナリオD：魔法都市の封印危機

三集落は重要経路と魔法資源に依存する。旧施設の保守技法が特定の学派と宗教組織に残り、原典は古語で書かれている。保守資源の不足または継承の断絶によって設備が劣化し、局地的な異変が起こる。

対策は輸送再開、原典の解読、施設の修復、住民避難、脅威拠点への対処から構成する。早期に条件を回復すれば出現前に解決し、放置や失敗で魔王が顕在化する。勇者は選定・認定・実績の複数経路で現れ、いなくても組織と他の人物が対策できる。

終結例は、封印の維持成功、顕在化後の討伐、再封印、隔離、都市放棄と避難、支配の再編とする。どの結果でも在庫、人口、施設、史料、物品の所在を確定する。成功なら無条件に元の繁栄へ戻すのではなく復旧が必要であり、敗北でも移住先で言語や祭礼が継続できる。

受け入れ条件は、前兆に根拠があり、対策の費用と時間が実際に作用し、役割人物の死で停止せず、終結後の社会状態と伝承が変わることである。途中の各段階で保存したデータから同じルール版の継続が一致する必要がある。

## 26.5 シナリオE：三世代・二学派・一つの遺物

創始者が技法を改良し、二人の弟子へ伝える。一人は別地域に移住して用途を変え、学派が分かれる。原典または印章が家を通じて継承され、一度失われて別の探索で発見される。

同じ起源から異なる技法・言語表現・伝承が生じ、長寿の目撃者と後世の伝承が食い違う場合も扱う。実際の系譜、本人が知る範囲、主張の内容を区別する。

受け入れ条件は、技法の派生元と伝授経路が同一でなくても表現でき、遺物IDが維持され、学派の名称変更で技法参照が壊れず、家系の変化と文化の変化を別々に追えることである。

## A.1 契約の位置づけ

## B.3 旧提案の更新点

「年齢18未満または近親なら全文化で婚姻を禁止する」という旧提案は採用しない。文化別の成立条件、親族規則、認定、個人意思へ置き換える。ただし、人物の成長・活動適格性の不整合を放置するという意味ではない。

言語生成を探索補助だけに限定する旧い位置づけは採用しない。言語史自体の生成と観察を主線にする。文明・経済・宗教は、単なるスコアの増減や文章上の設定だけで完成としない。

全面的な再実装や巨大な汎用エンジンへの統合は行わず、既存の境界を生かして一周する機能単位で進める。前提修正を理由に言語史や世界観の実装を無期限に後回しにしない。

## C.2 暫定設定の扱い

試作の三集落・二文化・一危機は、統合検証のための規模案である。人口率、危機頻度、同時アーク数、物流周期、言語変化の間隔、行動頻度は、未測定の提案値を完成バランスとしない。

パラメーターには単位、有効範囲、依存するルール版、設定意図、検証シナリオを添える。「年あたり」の年が内部の基準期間か文化暦かも明記する。安全な上限を持つ生成試行やデータサイズと、ゲーム上の制約を混同しない。

## C.3 主なリスクと抑制

| リスク | 起きる問題 | 抑制策 |
|---|---|---|
| 機能数の先行 | 互いに影響しない設定・数値が増える | 統合シナリオを完了条件にする |
| 正本の重複 | 回復・在庫・承認・歴史が矛盾する | 所有者と復元方針の一覧を維持する |
| 系譜と接触の混同 | 娘言語へ過去が逆流する | 段階固定と借用グラフの分離 |
| 文化の過度な均一化 | 全員が同じ制度・意志で行動する | 規則、例外、承認、個人意思を分ける |
| 粒度の爆発 | 全住民・全語・全商品の更新が重い | 集約人口、遅延生成、予定駆動、局所索引 |
| 誤情報と事実の混同 | 噂だけで現実が書き換わる | 主張と認識を独立した状態にする |
| シナリオの強制 | 勇者不在や早期成功で破綻する | 代替役割、複数終結、失敗後継続 |
| 履歴の削りすぎ | 保存後に現在や未来が変わる | 必要根拠保護、領域基点、継続比較 |
| 観察と生成の結合 | 画面を開くほど世界が変わる | 読み取り純粋性と乱数の分離 |
| 作者設定の矛盾 | 生成できない言語・成立不能な制度 | 検証CLI、根拠表示、小さなサンプル世界 |

## C.4 判断記録

採用時には、決定ID、選択した仕様、代替案、不採用理由、保存への影響、試験ID、公式計画アンカーを記した短いADRを残す。本書全体を毎回読み替えて意図を推測する運用にしない。未決定項目は、決定した版と残る不確実性を明示して更新する。

## D.3 文書の更新規則

本書を採用する場合、要求ID・試験ID・決定IDを維持し、仕様変更は版履歴へ記録する。実装が進んだ際は、該当節の状態を提案・実装中・実装済み・検証済みに更新し、検証済みには対象コミットと試験結果を付ける。過去の説明を消して現在だけを正しい履歴に見せない。

本書1.0で優先するのは、事実の整合、文化差、言語史、日常と大事件の往復を一つの小世界で成立させることである。その後に規模と内容を増やし、言葉・家・知識・物品・制度・土地のすべてに、起源と継承と分岐が見える世界へ発展させる。
