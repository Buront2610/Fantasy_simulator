# 冒険の個別予定と一区間の選択効果（統合設計書 §15.2–15.3）

## 計画・実装範囲

1. 新しい冒険の進行日を個別に保存し、世界共通の確率抽選から切り離す。
2. 選択の持続範囲を次の探索一区間に限定し、時間・危険・発見・補給へ反映する。
3. 期限と補給切れで帰還を開始し、手動選択・自動選択・保存読込・失敗後の再試行を検証する。
4. 全行程の時間と危険、長期世界のヘルスバンドを確認してからマージする。

標準ライブラリのdataclassで必要な保存状態を表現できるため、追加ライブラリは不要。

## 時間・補給・選択の契約

新しい出発は `AdventureSchedule` を持つ。`next_step_tick` はシミュレーターの絶対経過日と同じ単位。
進行が必要な日だけ計算し、待機日に進行抽選を行わない。手動選択はその時点から次区間を予約する。
保留選択を操作せず翌日へ進めた場合は、従来の方針に従って自動選択する。

基本間隔は `ceil(days_per_year / adventure_steps_per_year)`。既存の速度設定を引き継ぎ、
`adventure_steps_per_year <= 0` は予定の自動進行を停止する。出発時の基本間隔を保存し、
途中で設定値が変わっても既存の予定を再計算しない。

慎重進行は次の探索時間を1.5倍、危険係数を0.7倍、発見係数を1.1倍にする。
急行は時間を0.75倍、危険係数を1.2倍、発見係数を0.9倍にする。日数は切り上げ、
既存の確率上限・下限は維持する。一区間が終わると標準へ戻り、帰路に持ち越さない。
待機日数に比例して遭遇抽選を増やさないため、慎重進行が余分な抽選で逆に危険にはならない。

補給は人日単位で、全隊員が一日一単位を消費する。状態変更時に経過分を精算し、
表示時は同じ式で現在残量を計算する。開始量と期限は基本間隔6回分。
残量50%以下でlow、20%以下でcritical。期限到達または補給ゼロでは探索・保留選択を打ち切り帰還へ移る。
帰路の時間は必要。補給切れによる追加の飢餓ダメージはこの段階では導入しない。

予定・補給の更新も既存の冒険トランザクションに含め、記録が失敗した場合は日時・残量・乱数を復元する。
旧セーブに `schedule` がなければ旧進行方式で完了させる。保存の外枠やschemaは変えない。

## 未完了の範囲

この段階は物理的な経路・占領・対象移動の再計画をまだ扱わない。所要時間は既存の進行速度に基づき、
距離から計算した旅行時間ではない。次に経路と現在地、目的別の期限と物資調達を接続する必要がある。
目的・進め方・撤退条件の独立した選択、救助や実資産への成果、パーティー役割も引き続き実装対象。
§15全体の完了とは扱わない。

## プレイ検証

危険な入口での選択から一回探索して帰還する同条件を200個のseedで比較した。
主能力50、基本間隔10日、単独行動。深部への追加探索は両方式とも撤退し、
実際のシミュレーターの選択・予定進行・原子的適用・帰還処理を通している。

| 指標 | 慎重 | 急行 |
|---|---:|---:|
| 完了までの平均日数 | 25.34 | 18.29 |
| 平均補給消費（人日） | 25.34 | 18.29 |
| 負傷した試行 | 12.5% | 20.0% |
| 発見のあった試行 | 52.5% | 37.0% |

この条件での観測値であり、全目的・全能力帯における成功率ではない。
既存の30年×2seedを含む長期ヘルス検査8件も、バンドを変更せず成功した。
