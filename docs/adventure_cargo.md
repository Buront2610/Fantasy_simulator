# 実物を運ぶ冒険

設計書11.2・15.1の次の段階として、所有資源を指定地点へ預ける運搬を実装する。
結果画面の「所有資源を運搬する」から、健康で待機中の所有者、資源、実経路で到達できる地点、数量を選ぶ。
荷物は所有者が持つか、その所有者の現在地に保管されている必要がある。一便の依頼数量上限は10個。
通常の持ち物を含めた総重量はまだ計算しない。
運搬は所有権を変えず、保管者だけを発地→人物→届け先へ変更する。資産正本は前段階の台帳のみ。

## 実行と検証

- AdventureObjectiveのCargoLoadが一便の資源・数量・状態を保存する。便IDは冒険ID。
- 出発時に実在庫を積載。出発記録の失敗は積載・人物・予定・乱数を巻き戻す。
- 行程は既存の実経路・所要時間・補給・期限を使う。封鎖で経路を再評価し、未配達のまま帰還し得る。
- 到着後の作業で荷下ろしし、既存の危険判定・撤退判断も適用する。発見報酬を代わりに生成しない。
- 帰還で再配達しない。未達便の残る荷物は生還時に発地へ戻す。死亡者や遺失品から資産を瞬間移動させない。
- 配達によって探索進捗やダンジョン攻略度を上げない。荷物の移転と運搬の履歴を成果とする。
- 積載・移転・配達事実を台帳と正本イベントへ接続し、途中保存と途中失敗・再試行を検証する。

売買、報酬契約、生産需要に基づく自動出荷、運搬役の能力・重量別容量、道路容量の同時予約は後続。
このPRは手動の実物運搬を対象とし、経済・物流全体の完成とは扱わない。

トークン量は前回PR96の実測と比較する。実装範囲が異なるため、差分を同一作業での節約率とは呼ばない。
軽量チェック→重点テスト→最終CIを使い、失敗ケースからの証跡回収のために同じ長期計算を繰り返さない。

固定条件20ケースでは、数量1〜10・経路長の違い・途中封鎖・途中保存を組み合わせ、
通常便の合計55個が配達、封鎖便の合計55個が発地へ返送された。全ケースで資源総量26と
保存復元後の資産台帳一致を確認した。これは固定した経路・在庫条件の検証であり死亡率や経済全体の評価ではない。
