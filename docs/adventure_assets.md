# 有限な戦利品・資源・固有遺物

## 計画と正本

設計書5.2、11.1、14.5、15.6、17.1の接続として、Worldに資源在庫と固有遺物の単一台帳を導入する。
人物と地点に同じ在庫を複製しない。所有者と保管者を分け、持ち物は人物の実際の移動に追従する。
既存loot_summaryは履歴表示として残し、旧セーブの文字列から資産を捏造しない。

各地点には初回の探索で有限の発見候補を一度だけ配置する。月銀20、魔物素材6、護符1、史料断片1を
初期配置として明示する。取り尽くした地点を自動補充しない。月銀・素材は数量、護符・史料は個別ID。
初期配置は遺物の製造履歴ではない。製作者・製造年・読めない刻文の言語段階が不明なら不明のまま残す。

## 実行と検証方針

- 発見は地点から実物を移す。資源は同行者へ整数で分配し、遺物は一人の保管者へ移す。
- 帰還で再支給しない。所有者が死亡しても物品を消さず、保管者と所在の区別を維持する。
- 譲渡・落失・再発見は同じ遺物IDと移転履歴を使う。拾っただけで既存の所有権を上書きしない。
- 護符は有限の3回の使用で実際の冒険被害を軽減し、効果と消費を同じ原子的処理へ含める。
  被害者本人、次に同じ隊の生存隊員（人物ID順）が保管する護符を使う。保管者は変わらず、
  消費記録に保管者（holder）と守られた人物（protected）を分けて保存する。
- 持ち物の遺失は、その被害で保管者が重傷以上へ悪化した場合に限る（護符による軽減後の結果で判定）。
  史料断片の所持だけで、未実装の読解や技能獲得を捏造しない。
- 新しい台帳は初日から保存し、不正なID・参照・重複・数量を境界で拒否する。既存セーブは空から開始。
- 発見・消費・帰還・保存復元・途中失敗の巻き戻し・二重適用防止・所有／保管の分離を検証する。
  長期の資源収支・世界ヘルス・保存量も計測する。

在庫の生産・物流、制度別相続、知識の読解、取引価格、具体的な医薬品の調達は関連する後続要件として残す。
この段階で設計書全体や経済モデルの完成とは扱わない。

## 測定と保存容量

30年・seed 7/42では生存19/17人、イベント444/514件。初期配置済み地点は4/6、固有遺物8/12個、
月銀80/120、素材24/36で、初期配置からの総量保存とSimulator保存復元後の台帳一致を確認した。
この自然進行では護符消費は0回だったため、効果自体は別の戦闘実験と消費・枯渇の結合テストで確認する。

能力値20〜80・危険度40/80の500件の独立した戦闘では、同じ戦闘結果への護符の適用で
負傷289→138件、重傷138→0件となり、消費289回。無傷では消費しない。
各ケースは未消費の護符を持つ単発戦闘であり、生涯生存率や連戦の無限防御を意味しない。
3回消費後の枯渇と4回目の通常負傷、重傷時の遺失、途中失敗時の消費取消しは結合テストで検証する。

初回計測のworld保存量は1,326,521/1,505,048 bytesで、後者が既存1,500,000 bytes基準を超えた。
未確定の遺物メタデータを省略しても復元時には不明値を保ち、同じ30年後のsnapshotで
1,325,265/1,503,164 bytesへ縮小した（削減1,256/1,884 bytes）。台帳のcompact JSONは6,763/11,319 bytes。
world全体の増分にはJSONの整形と正本イベントへの資産参照も含む。前段階のseed42の保存量からの
増分は19,323 bytesで、必要な在庫・履歴を削らず、容量バンドのみ1,530,000 bytesへ変更する。
人口・婚姻・移民・危険・戦闘・魔法・イベント件数のバンドは据え置く。

容量比較は同じ未復元snapshotの台帳部分のみを再シリアライズしている。既存ロード処理は空の言語状態・
地名履歴・関係タグの参照を正規化するため、全snapshotの文字列一致を資産の正しさと混同しない。
復元後のworld容量も1,328,967/1,506,560 bytesで新バンド内。資産の値・履歴・残り回数は一致している。

資産は外部ライブラリを必要としない値オブジェクトと整数台帳で実装した。冒険・役割・原子的処理・
経路・保存・履歴保持122件を確認し、その後の局所整理・保存省略は資産19件で再確認する。
長期実行後のsnapshotを保存し、保存処理だけの変更では同一状態を使って容量を比較する。
これにより毎回30年を再実行せずに比較できるが、保存互換テストと最終CIの全件検証は省略しない。

死亡した保管者の所持品は現在その人物に保持され、表示は最終所在となる。冒険の重傷による遺失は
実地点に移り再発見できるが、自然死時の遺産整理・相続は今後の実装対象である。

## レビュー後の修正（護符の隊内共有・遺失条件）

目的付き冒険の実戦は前衛が担当する一方、護符は発見順の隊員へ渡るため、前衛以外が持つ護符は
使われなかった。暫定仕様として同じ隊の生存隊員が持つ護符で被害者を守る。死亡した隊員の護符は使わない。
旧来の保存データの消費記録には protected がなく、読み込み時は保管者本人の消費として扱う。

遺失は従来「軽減後の悪化段階数2以上」で判定しており、負傷済みの人物が1段階で重傷になっても落とさず、
設計の「重傷時の遺失」と一致しなかった。結果の健康状態で判定するよう修正した。遺失が増える方向の変更のみ。
存在しない遺物IDの移動はKeyErrorではなく参照不正のValueErrorで拒否する。

30年・seed 7/42の自然進行は修正前と完全に同じ結果（生存19/17人、イベント444/514件、
保存1,325,265/1,503,164 bytes）で、護符消費は0回のままだった。原因は隊の形成頻度で、
seed42の目的付き冒険9,905冒険日のうち複数人の隊は21冒険日しかない。共有規則は結合テストで検証し、
自然進行で隊を増やすかは冒険開始のバランス変更として別途扱う。バンドは変更しない。
