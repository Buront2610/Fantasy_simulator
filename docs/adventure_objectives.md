# 冒険の目的・進め方と救助

## 実装計画

- 新規冒険は目的（探索／実在人物の救助）、冒険中の基本の進め方、既存の撤退条件を独立させる。
  一区間の選択は基本の進め方を上書きし、その区間終了後に基本値へ戻る。旧セーブには目的を捏造しない。
- 救助情報は同席している負傷者、または届く範囲に広まった負傷イベントの噂から得る。対象IDと根拠を保存する。
- 出発・各予定ステップで対象の生死・健康・現在地・所属を確認し、移動なら行程更新、回復や別隊の救助なら失効する。
- 同じ地点へ実際に到着し、処置時間と物資を使った後で救助する。対象を救助隊へ移し、旧隊の所属も原子的に更新する。
- 健康を一段階改善し、実際の帰路を同行する。人物の現在の健康を帰還判定に使い、古い負傷値で再び悪化させない。
- 関係・個人史・評判・正規イベントへ成果を反映し、途中保存と失敗時の巻き戻しを検証する。

既存の経路・噂・人物・イベントの契約を使い、外部ライブラリや抽象的な汎用目的エンジンは導入しない。
討伐・運搬・設備修復は各対象と実際の成果まで接続する段階で追加する。ラベルだけ追加して完了とは扱わない。

## 実際の時間・消費と互換性

探索と救助の二種類をまず接続した。旧policyは旧セーブの確率計算用に維持するが、新規冒険は目的と
基本paceを保存し、policyの危険・発見補正を重ねない。基本paceは往復の区間日数にも作用する。
画面の一区間の選択は探索一回だけ上書きし、その後は保存した基本paceに戻る。

救助情報が届いていて参加可能な人物がいれば、通常の年率の出発抽選より先に一日一隊まで出発する。
同席での目撃、または正規の負傷・容態悪化・戦闘イベントに由来する噂が必要。噂のspread_levelを
通行可能な経路の最大ホップ数として使う。既に出動中／同行帰還中の対象には重複出動しない。
強い敵意のある人物は参加せず、現地に届く経路があることも必要。

救助の基本間隔は通常設定を上限7日へ短縮し、自動隊は急行を選ぶ。通常探索の数か月単位の抽選待ちで
重傷者を放置するのを避けるための時間尺度で、距離は引き続き区間費用から計算する。
治療作業は探索相当の時間を使い、通常の日々の人日消費に加えて基本間隔2回分の物資を使う。
治療は重傷→負傷、瀕死→重傷の一段階。治療後は人数増を帰路の消費に反映する。

旧隊の物資は移籍日まで旧人数で精算する。一人隊は救助引継ぎで終了し、他の隊員がいれば残員の隊は
帰還へ移る。救助隊・旧隊・人物・関係・イベントは失敗時にまとめて戻る。帰還時は現在の健康を使う。
救助成功は処置と合流時点のrescuedと、生存帰還時点のcompletedを分ける。
救助では未探索なのに探索進捗やダンジョン制圧度を与えず、生存帰還で現地の評判を8増やす。

## 残る検討

噂の距離モデルは個人別の知識台帳ではない。隊員の職能・運搬能力、実在庫・医薬品の種類、現場での
高度な治療判断、道上の遭遇は今後接続する。今回の補給は保存された遠征予算で、実在庫調達ではない。
旧rescue policyのセーブには対象を捏造せず、objectiveなしの既存方式で完了させる。

## 検証と範囲

二年の固定シード7/8/9で非加齢イベントは20/10/26件。seed9は4回の出発、3回の到着、3区間の移動などを
記録するため、同テストの非加齢イベント上限を24→28へ調整した。総イベント上限36、生存者、活動月数、
噂の上限は維持する。長期ヘルスバンドも変更しない。

4地点・能力50の一人の救助者・遠隔地の重傷者・通常イベント0・90日進行を50シードずつ比較した。
初期の負傷情報なし／ありで、治療31/40、生存帰還21/40、対象生存50/50だった。初期情報なしでも月末に
噂が生成され、その後に出動する場合がある。これはこの条件の観測値で、普遍的な成功率や生存率改善ではない。
再現スクリプトとJSONはタスクのadventure-objectives証跡ディレクトリへ保存した。

## 検索の実行効率

噂ごとのget_event_by_idが、互換編集を検出するため全履歴のシグネチャを毎回再計算していた。
判断処理内で現在のevent_recordsから参照表を一度作り、以降の噂を引く方式に変更した。
判断をまたぐキャッシュは作らず、履歴の直接変更も次の判断ですぐ反映する。
1000イベント・30噂・20回の同一検索で68.402秒→0.041秒、全結果一致を確認した。
これは当該検索の条件付き測定で、シミュレーション全体やモデル料金の削減率ではない。
遅延していた20年の死亡シナリオを含む26テストも59.41秒で通過した。
